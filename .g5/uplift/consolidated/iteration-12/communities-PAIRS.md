# Next workflow draw: raw weak components and label propagation

Frozen from canonical algorithms.op.wcc/.cdlp/.cache and published API/USER_GUIDE
before inspecting their current implementation bodies for this survey. Existing
published feedback explicitly leaves WCC/CDLP consumers/census/cache coverage
partial; this is source-informed selection, not a new blind benchmark case. Only
allowed published feedback was consulted; no private evaluator inputs.

Predicted decisions to preserve on both prospective snapshots:

1. Weak components ignore orientation: a->b and c->b form one component labelled
   its minimum ID; a persisted isolate labels itself. Reversed arrows must not
   change that partition. Every current default-graph node must be present.
2. WCC runs to a fixed point, while an exhausted explicit round budget must refuse
   instead of returning an intermediate partition. Retain a passing sufficient
   budget and a deliberately too-small budget; derive scan/round behavior from raw
   adjacency rather than supplying a converged flag or component map.
3. CDLP is synchronous: a two-node link swaps labels on odd rounds and returns
   initial labels on even rounds. A self-loop adds no vote; stable/no-change and
   round-limit termination are distinct. Oscillation is documented, not a bug.
4. Physical edge multiplicity changes a CDLP majority; a tie uses IRIS collation,
   not an invented lexicographic order. Derive vote counts from selected raw edges,
   including direction/self-loop exclusions and keyed count/provider premises.
5. Fresh computation, successful empty census and failed census differ. A two-engine
   ordinary add/remove isolate history must be checked against actual cache stamp
   inputs. Existing generic caches/P acache node-token counterfactual are substantive
   partial hits, not proofs of the current node membership/key producer.
6. Public engine/store/native/list/result wrappers must preserve the map and error
   distinctions actually generated by the raw algorithm. Provider-fixture maps are
   insufficient to establish the algorithm itself.

Possible next model: raw nodes/edges -> selected weak neighbors/vote multiset ->
actual ordered/in-place WCC rounds or synchronous CDLP rounds -> fixed/limit result
and complete node reader, then actual cache membership stamp/return consumer.
Which portions are implemented and duplicated across routes is not yet answered.
Any narrower source-specific contract must retain the missed routes in the ledger.
