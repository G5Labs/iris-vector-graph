## What the actual functions decide

`produce` reads complete current node labels/properties and statement tuples/
qualifiers, independently writes those maps and derives each record's actual
prior/new/snapshot. A new create emits an empty node or tuple-only relationship,
then separate label/property/qualifier operations. Existing upsert preserves
content. Duplicate labels and identical values emit nothing. Removes require a
live attribute; reader removals remain idempotent. Reserved node properties are
exactly `id`/`__graph`. Public null/container refusal, raw null flags, empty text
and text `null` are distinct typed boundaries; the full fold subsequently maps
a raw setter's None to empty text. Label presence records carry empty text.

`request_ops` expands raw semantic Node/Rel/Replace/Detach requests, derives a
relationship identity from the current tuple index or its own next counter,
and emits default relationship deletions before a detached node deletion.
`pre_error` preserves deleted-identity and reserved/existing/weight/key-carrier
ordering; `execute`, `requests` and `commit` stop at the first refusal, roll back
the content/counter/records and clear deletion context only between revisions.
Stamping derives revision and ordinal from the emitted sequence. `history`
starts with empty content/counter1 after empty revision1 metadata; failed batches
do not consume a revision sequence. No expected graph, expected delta, supplied
record prior or snapshot-truth flag decides this producer.

The general record reader contains the complete content maps. Node create
resets content and ignores its new payload. Missing-entity updates are ignored.
Node delete has no implicit relationship cascade. Relationship graph is read
from the tuple, with None/empty/NUL default normalization. Statement-ID maps,
tuple reverse index and `as_comparable` are different readers: two IDs for one
tuple survive in statements/export, while tuple/comparable selects the later
one. Deleting the older ID unconditionally removes the tuple index even when
the later ID survives. `theorem_duplicate_tuple_views_remain_distinct` retains
that actual behavior rather than assuming a bijection.

entity-count projection, not an assumed refinement. The full run checks the
