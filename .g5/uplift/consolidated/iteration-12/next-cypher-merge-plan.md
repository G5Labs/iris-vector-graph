# Cypher MERGE continuation survey

The before census leaves980 Cypher members unlinked. Recent pinned history and
known regression tests selected typed MERGE actions as a concrete consequential
path independent of the current two builders. The frozen PAIRS precede this
implementation inspection. Native18 comparisons agree across25 actual query

The parser produces actual expression trees. `_merge_action_list_value` folds
supported literal/parameter arithmetic, text and boolean expressions to typed
literals, and separately serializes admissible node list values. `_reads_only_properties`
walks expression nodes once, excluding nested binding constructs and rejecting
unprovided variables. Own-node reads use the SET value path in the actual target
row. Other MATCH-bound node reads can use `_merge_action_typed_sql`, which checks
the available alias/frame and adds only self-contained joins; it restores the
temporary translator state even on exit. Parameter markers, additional WHEREs,
pair placeholders or other unsupported context leave that branch. The general
RETURN-style fallback in `_merge_action_value_sql` still casts to text. Therefore
the recent typed cases are not an arbitrary-expression type-preservation theorem.

`_merge_rel_value_sql` reads the relationship's own properties or typed parameters
through qualifier writes. A property of another variable explicitly raises
SyntaxError before SQL. Relationship raw text still passes through the documented
text decoder, unlike node typed values. Map replacement and arithmetic/coercion
deviations from the canonical conformance owner remain distinct obligations.

Branch capture matters independently of expression values. Keyed ID MERGE derives
created/matched capture sets before insertion. General ON MATCH captures row IDs
before or after insertion according to the incoming-row situation; with multiple
incoming rows the first may create and later rows may match it. Pre-edge action
ordering prevents ON MATCH from firing on the edge just inserted. Later DML uses
the captured IDs instead of rerunning a predicate changed by an earlier assignment.
The actual executor expands capture placeholders and owns one write transaction;
caller transaction and rollback are real separate source roles, not settled by
checking the translator's emitted SQL strings.
