# Actual census fallback provider challenge

Frozen before executing this panel. The public community contract includes
isolates; `_loners` documents its SQL fallback as the same census as native
LonersJson. A self-loop node is a loner with loop=True; an isolate has False;
nodes with an edge to another node are excluded. Test fresh default and named
task-prefix neighbors, with native class calls available and with only the
LonersJson provider forced to raise before returning any data. All subsequent
SQL is actual and no row/answer is supplied by the fault adapter.

Both census paths should agree under faithful native/SQL edges. Public WCC/CDLP
should still include the default isolate when they take the fallback. An explicit
source concern to test, not assume: the fallback binds empty graph as'' beside
COALESCE(column,''), while some native host-variable paths bind'' as SQLNULL.
If DB-API shares that behavior, the default fallback may lose nodes; a nonempty
named graph is a passing neighbor. Driver binding must be observed, not inferred
from native host-variable comments or a SQLite/pure fixture.

This is a source-informed provider challenge, no blind/private grade. Native
unavailability is injected in process, not an organic outage. No class deletion,
metadata alteration, global erase, security exercise, source patch or new model.
