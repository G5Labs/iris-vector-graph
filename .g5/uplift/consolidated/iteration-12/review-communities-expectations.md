## Necessary roles and acceptance conditions

Expected chain is raw Algorithms.WCCJson/CDLPJson selected coordinates and old-label
scans → synchronous new map/changed counter/budget → actual JSON/map rows → store
strict membership reader/cache → engine _kg_WCC/_kg_CDLP → fresh _loners →
_edgeless.complete_labels → public kg_WCC/kg_CDLP. Native paging and SQL loners
are separate actual readers. Adjacency/node writers and algorithm-cache histories
remain existing independent roles unless this package truly represents them.

For WCC require generic path-derived reachability and minima, monotone propagation,
finite sufficient bound including unchanged confirmation, and actual explicit
budget refusal. For CDLP require raw frequency accumulation, old-map synchrony,
self/tie/no-vote rules, parity and bounded/fixed termination; never require universal
convergence. For final membership derive current loners from raw nodes/edges and
compose them with a correct reused core. State faithful mirror/endpoints-in-node
and stable snapshot/provider premises explicitly. A public answer may otherwise
retain orphan/stale core IDs; completion does not filter them.

Controls must alter deciding source rules/actual observation against unchanged
input-derived expectations: missing reverse scan, wrong budget/no-change order,
in-place CDLP writes, included self-loop, wrong vote/tie rule, overwritten existing
label or omitted live completion. Separate true Python mutations, source ports,
representation changes and oracle sensitivity. Ordinary false obligations earn
credit; parse/type/resource/lookup failures do not. Preserve every original
prediction, partial domain, failed attempt and exact before-mutation inputs.

Known P acache/graph_structure, procedure_results and routing models remain
substantive prior hits. They do not prove this raw kernel plus cached-core/live-
membership consumer chain. No inference of whole body, full native collation,
all keyed-edge policy or every cache writer is authorized by this panel.
