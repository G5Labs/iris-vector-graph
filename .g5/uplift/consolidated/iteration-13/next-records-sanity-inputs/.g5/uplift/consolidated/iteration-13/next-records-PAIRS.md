1. Raw node, label and property rows for requested IDs must derive full records; no supplied hydrated record, inclusion flag or prepared property map. Typed scalars retain prior node_read limits.
2. get_nodes defaults to one default graph and passes an explicit named graph through every child/existence query. Same ID in another graph cannot contribute its label/property or existence. export_graph_ndjson's public signature has no graph argument and docs promise default graph only; named hydration is a distinct passing neighbor.
3. Requested order and repeated IDs survive batched hydration; absent IDs without child rows disappear. Empty request produces no reads/records. These are known node_read hits to retain, not new whole-workflow discoveries.
4. An unlabeled/propertyless persisted node remains a record, while an orphan child row can make a requested ID readable without a node row under the current owner. Which IDs export initially enumerates is a separate raw census decision; do not infer that all arbitrary readable IDs are exported.
5. A full record derives structural id and label list plus typed property fields. Property id/labels use p_id/p_labels without replacing structural fields. Existing colliding p_id/p_labels are an unresolved alias rule; do not choose a new preservation policy or advertise physical inverse reconstruction.
6. Repeated raw label/property rows and physical keyed edge multiplicity require explicit producer uniqueness/equality premises. Preserve observed list/multiplicity behavior; SQL order is not a blanket canonical ordering promise.
7. Export should construct node-kind records from actual hydrated node data with id, labels and a properties map, then edge-kind records from actual default structural edge rows. It must not accept a supplied node/edge deciding answer or count.
8. Actual NDJSON output is one JSON object per line, nodes before edges. Counts should derive the actual written records, with the healthy file's parsed line count matching node+edge counts. JSON byte/order/driver providers stay explicit.
9. Healthy default-graph A/B/C plus an unrelated named graph must produce only default nodes and structural edges. Temporal edges use a separate export; their exclusion should be derived from the source selection rule without expanding this survey into temporal protocols.
10. Edge records carry source, predicate, target and qualifiers as the source/docs specify. Ordinary multiple raw edge rows must not collapse merely because they share endpoints/type, unless a source uniqueness frame explicitly supplies that fact.
11. Existing import reads the exported kind/id/labels/properties/source/predicate/target/qualifiers format. On a fresh healthy destination, plain nonreserved properties/labels/edges can be compared semantically; duplicate import counters are processed lines, not rows created. Do not promise a generic export/import inverse.
12. Alias projection, canonical boolean/list/map decoding and writer normalization can change the physical property representation even if ordinary final reads agree. Preserve such a boundary as existing alias/value behavior rather than silently equating raw storage with reported records.
13. No ordering of all records beyond nodes-before-edges is inferred from docs. A proof may use an admitted raw SQL order and must derive the resulting serialized sequence/counters from that order.
14. A normal call must report its actual output rather than fabricated success/empty records if a read/write raises. Whether a partial file can remain is a source boundary to inspect; healthy feasibility probes will not inject failures or claim atomic export/transaction/durable filesystem guarantees.

Prospective material missing distinction: raw node-ID census plus whole-record hydration and property-key projection through an actual node NDJSON line and the existing import reader. A wrapper-only call to the already-modeled scalar reader would add no substantive claim. Alias and scope boundaries, and a line/count relation derived from actual record construction, could distinguish a new full-record model from the old inclusion/scalar/import-count hits.
