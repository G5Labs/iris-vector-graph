2. **Actual node-parent merge is a producer, not a blanket premise.** Parent reported a native DISAGREES receipt while extending merge tests: preexisting B node and an A/B same-ID archive cause generic nodes merge guard to skip A's parent; A's vector then fails its FK. Root matched inherited `bug-plt-004`/`F-1802`, preserving the intended complete-restore oracle. The first composition theorem's `dst.parents.contains` premise is conditional, not a proof that restore establishes it. Final `restore_parent` represents the first-column node-ID merge guard, and `theorem_merge_parent_collision_blocks_vector` derives the suppressed parent, vector FK refusal and absent final read. The positive export/restore theorem remains explicitly conditional on a valid destination parent. This is a modeled inherited exception, not a repaired product.
3. **Index state is the helper result, not independent physical-index equality.** Model `build:bool` represents `_attempt_route_index`'s result, and the initial native observation read only registry `index_state`. Final native receipt now also records `GraphSchema.hnsw_indexes` catalog results: normal/fallback routes have the expected index; injected-before-CREATE refusal has none; failed record retains `present` even while the catalog has none. `record=false` appropriately retains old status. A stronger physical-index claim needs catalog observation and a provider premise about create/commit failures; helper catches a commit error after CREATE too. Two injected-before-CREATE/refused-record cases establish helper/error propagation only. They are not native provider-failure observations.
4. **Decoded domain and phase boundary.** `Width::Falsy` abstracts Python falsey values; `Present(0)` can represent truthy text `"0"`; `Invalid` represents a truthy unparseable value. Model does not prove Python JSON/int conversion. `load` is reached only after positive-width preparation: invalid preparation already counts skipped archived rows, and the actual controller continues without loading. Parent membership, valid route-name/table identity, valid row ID/vector and successful provider commits remain explicit boundaries.
