## 0. Key findings (summary)

1. **Fixture bug in R281/R290 (product intent not kept by the fixture).** The fixtures read
   `was_enabled = bool(engine.ledger.meta().get("enabled"))` (test_460_r281_ledger_post_commit_graph_e2e.py:52,
   test_460_r290_ledger_node_ops_graph_e2e.py:66). `Graph.KG.Ledger.Meta()` (iris_src/src/Graph/KG/Ledger.cls:143-156)
   returns `ok, state, strict, max_ops, recon_bound, head_seq, head_id` and has **no `enabled` key**. As a result
   `was_enabled` is always False. Each fixture calls `enable()` every time, and **always runs `ledger.disable()` at
   teardown**, including when the ledger was already enabled before the module. That disables the ledger of the shared
   "rag" scratch namespace. Both docstrings promise "disabled after it if it was not enabled before". The R150 and 470
   files read `meta().get("state")`, which is correct.
2. **A hard-coded namespace is dropped and rebuilt.** `test_460_upgrade_ledger_history_e2e.py:28` uses `NS="IVG262FX8U"`
   and gates only on the container (`ns262.requires_container`). Its fixture calls `build_release_namespace.build()`,
   which calls `make_scratch_namespace.recreate`: it DROPs and re-creates the namespace and its database. It also runs
   `git worktree add` for v4.5.1 under `~/.cache/ivg-bench/releases`. This gets past the R191 guard
   (tests/unit/test_460_r191_scratch_namespace_env.py only spots direct `ns262.recreate/drop` calls). The file is also
   absent from gate.py GROUPS, so it runs in any e2e session where the container is up.
3. **Contract drift (spec 213) contradicted by the 4.7.0 tests.**
   - ledger-api.md:26 lists `LedgerTransactionOpenError` among `commit()` errors. test_470 asserts that `commit()`
     nests in the caller's transaction and does not raise.
   - ledger-api.md:22 lists only `LedgerLockTimeoutError` for `enable()`. test_470 asserts that `enable()` (and
     `redact()`) raise `LedgerTransactionOpenError` inside a caller transaction.
   - changeset.schema.json `DiffEntry.entity_kind` is `["node","rel"]`. test_224 (and CHANGELOG:4802) require
     `"temporal_edge"`.
   - The schema's `Changeset` (`additionalProperties:false`) and its `Op` enum leave out `post_commit_properties` and
     `create_temporal_edge`. `Changeset.to_wire()` emits both (ledger/changeset.py:347-360). The schema-conformance
     unit test (tests/unit/test_ledger_changeset.py:70) validates only a changeset that has neither.
   - `CommitError.error` has no `idempotency_redacted`, but Ledger.cls:471 emits it.
4. **Doc vs product: "Retries".** USER_GUIDE.md:1102 says "Committing the same actor and operations again returns the
   first revision with `replayed=True`." The server replays only when an `idempotency_key` is bound (Ledger.cls:457
   `If (tKey '= "") && $Data(^IVG.Ledger("idem", tKey))`). Without a key, a repeat makes a new revision. Every replay
   test passes a key (test_ledger_us04_idempotency.py, test_224:109-129). No test checks the doc's wording.
5. **Graph scoping is inconsistent and untested.** R290 scoped LedgerApply node writes to the default graph
   (`DEFAULTGRAPH` LedgerApply.cls:15). Some reads stay graph-blind:
   - `NodeExists` (LedgerApply.cls:79-84), genesis `Capture` (LedgerGenesis.cls:18-21) and `read_canonical`
     (replay.py:600-608) remain graph-blind.
   - A node id that exists only in a named graph therefore passes the existence check. Its label or property is then
     inserted into the default graph with no default-graph node row, and `delete_node` records a deletion that removes
     nothing.
   - No test covers these cases, and neither R281 nor R290 ever calls `verify()` on its two-graph fixture.
6. **The 4.7.0 caller-transaction work leaves these promises untested:**
   - a refused or failed changeset inside the caller's transaction only rolls back its own level, so the caller's rows
     survive (Ledger.cls:397-408 comment; CHANGELOG:422);
   - autocommit-off as a caller transaction (USER_GUIDE.md:267-268);
   - uncommitted revision visibility to a second connection (USER_GUIDE.md:262-265);
   - another connection's `commit` raising `LedgerLockTimeoutError` while the caller holds the head. The test takes the
     raw Native API lock with timeout 0 instead (test_470:235-236). Lock-timeout-to-error is covered separately by
     tests/integration/test_ledger_lock_and_chunks.py:36, which uses an external lock holder.
7. **Shared-namespace side effects in tests outside the ledger files.**
   - These enable the ledger on the session namespace (IVG_NAMESPACE, default USER) and never disable it:
     - tests/integration/test_224_temporal_changeset_e2e.py:26
     - tests/integration/test_218_post_commit_properties_e2e.py:19
     - tests/integration/test_214_import_ndjson_graph.py:68
     - tests/e2e/test_adjacency_owner_live.py:144-145
   - `ledger_reset` (tests/conftest.py:1278-1323) is DESTRUCTIVE. It runs before and after each test: KILL `^IVG.Ledger`
     plus `%KillExtent` (via `Graph.KG.Ledger.PurgeAll`, Ledger.cls:242-248), on top of `iris_master_cleanup`
     (`Graph.KG.Eraser.EraseAll` on the whole session namespace).
8. **Weak or vacuous assertions.**
   - test_262_alt_schema_paths.py:464 checks `node_id = 'altrd:x'`, but the node written was `'altrd|x'`, so the count
     is always 0.
   - test_218:100 asserts only `isinstance(result.post_commit_applied, bool)`.
   - test_224:160-172 accepts either outcome. If the commit succeeds, nothing is asserted.
