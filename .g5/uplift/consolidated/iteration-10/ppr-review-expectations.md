## Source-specific checks before candidate acceptance

The recurrence must preserve raw NodeSeeds->eligible hops->degree/scatter->restart
and actual map/change/held behavior. Normal native no-exclusion divisor comes from
Adj.Degree and can read a matching-generation cache; mathematical recount equality
alone does not prove that cache protocol or writer histories. Python fallback
reads real SQL rows; native uses raw out/in coordinates with '#' multiplicity.
Their equality needs a declared stable, closed provider relation.

Nonnegative raw count includes zero numerically. If that carrier is admitted,
inspect map-presence semantics: Run can assign newRanks(v)=0 via a zero-count
coordinate while another outgoing count makes deg>0. RunJson itself ranks map
entries, whereas the engine class-fast path filters score>0. A model using only
positive support must either retain this distinction or explicitly qualify its
reader correspondence; this is a source review question, not a predicted new
ordinary-writer bug or a request to broaden provider probes.

Exact real arithmetic and an abstract integer-atom node/type frame can support
mathematical recurrence and counterexamples without claiming arbitrary native
floating $Normalize, string collation, JSON/coercion, raw typed-prefix parsing,
Unicode or external Native Reader fidelity. Check that exclusions, graph selection
and counts are produced from raw fields rather than supplied filtered adjacency.

Acceptance requires initial/iteration/final-reader contracts derived from the
actual preparation, named isolated controls failing ordinarily rather than only
elsewhere/resource limits, executing real Python fallback and wrappers over a
relational adapter, source-port qualification for ObjectScript, current hashes,
and selected actual upstream units with sockets blocked. No native calls are
authorized for this reviewer. A finite-step recurrence proof is not infinite
convergence or a universal floating/native body proof.
