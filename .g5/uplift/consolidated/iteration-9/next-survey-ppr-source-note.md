The strongest first source challenge is an **existing hit**, not new discovery:
`IRISGraphStore.execute_ppr` :2231-2275 hashes seeds/damping/iterations/reverse/
exclusions/limit/tolerance and uses `_cached_algorithm`. Cache lookup/front memo
trusts the adjacency token and caches even an empty score payload. The engine
then calls `_ppr_every_node`: empty scores return{}, nonempty rows are ranked and
supplemented from the current node table, subject to limit/cap. This means a
cached empty answer before an absent seed is created is materially different from
adding an unrelated zero-score node to a nonempty cached answer. The latter
reader can reread nodes; it is not sound to claim every node-only change is missed.

The absent->isolated-seed scenario is already **F-1004 / bug-plt-017**, with native
evidence and explicit iteration3 reconciliation. Its deleted-node premise was
refuted because Eraser advances the token; do not revive that allegation. P
`acache_l1/l2` models the cache protocol/node-token reviewed remedy and as-built
control, not numerical PPR. C pagerank_admission is global PageRank only, explicitly
not PPR. This source check preserves those hits rather than creating another
cache-boolean model or counting a new bug.
