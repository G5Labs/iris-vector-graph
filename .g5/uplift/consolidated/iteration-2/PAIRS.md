## Producer, consumer and assumption challenge

- Ledger: changing raw node existence changes relationship admission; changing record production to drop prior values fails the revision theorem. Leaking the successful prefix fails rollback. The Python fixture cannot establish real server writes, so that binding stays Inspected and is expressly not an end-to-end native claim.
- Reconstruction: replace the actual producer of the limit (zero/unset metadata fallback), replace named cutoff or change peak to final-only: the deciding claims fail. The consumer is the actual public named reader, not only an unbounded record fold. Full content and diff remain outside the formal projection.
- Fusion: first→last rank production, missing-rank contribution and dropping the second leg all fail. Swapping provider catch decisions fails the wrapper theorem. Empty success is not treated as failure. General sort, float accuracy and all other fusion implementations remain separate gaps.
- Bulk deletion: the first atomic-provider sketch was challenged by _delete_in_scope and the store. Reifier cleanup can fail after primary removal; store chunks can commit separately. The final model includes primary-then-cleanup partial effects and the actual error-count consumer; it does not assume that every caught error rolls back. Full database/store atomicity is not observed.
