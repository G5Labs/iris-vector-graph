1. Instrument (commit under .g5/Verus_verification/census/ and .g5/Verus_verification/tools/census.py)
   - blocks.tsv: one row for every one of the 406 blocks: block id, page, kind (I/D), sha256 of the block's own governing text (lead + bullets + tables + exceptions, from the anchor up to the next anchor/heading; exclude the "### id" metadata section) so a later seal can detect reworded blocks, enumeration status (complete | partial | not-started), obligation count, structural-zero flag with reason, parent/children as declared in metadata (Children/Expands), owners checked for a structural or restatement claim.
   - obligations.tsv: one row per obligation, stable id `<block>#oNN`. Columns at least: id, block, text locator (lead | bullet N | row N | exception N | working-assumption N, with a short quote prefix), obligation statement (a paraphrase that keeps its conditions), distinguishing cases (the neighbouring inputs/histories that must yield different results), observation/reader, model and property locators (path::item, several allowed), domain/premises, representation grade (full | partial | absent | unassessed), design check (proved | bounded | refuted | unchecked | none) with receipt path, as-built correspondence (binding receipt or native receipt, its verdict, or none), parent entailment (for a parent: the child obligation ids and the argument, or "residual"), gap (the missing distinction, decision, effect, reader or premise), grade source (reused: coverage.md row / model manifest / iteration handoff; or new: inspected here), iteration.
   - excluded.tsv (or an exclusion column): rationale, undecided alternatives, pure navigation, evidence annotations ("Iteration NN ... observed"), with reason. Keep a stated working assumption about current behaviour as an assessable obligation within its scope; a working assumption that only states a preferred policy option is an undecided alternative.
   - tools/census.py: deterministic; parses the current ontology, fails if a block is missing from blocks.tsv, an obligation names an unknown block, a block hash changed since its row was graded (report STALE, do not silently pass), a model file or named item in a locator does not resolve, or a cited receipt path does not exist. Prints per-block counts (full/partial/absent/unassessed, percentage or N/A), per-page and pooled totals over the enumerated scope, and the count of obligations with a passing design check over their full stated scope, with bounded and refuted results identified separately. With unassessed entries print lower bound full/total and upper bound (full+unassessed)/total. While any block is not-started or partial, print "enumeration incomplete: whole-foundation percentage unmeasured" with the enumerated block count, and never print a whole-foundation percentage. Write census/summary.md from the same run (regenerating twice gives identical bytes). Add a short README in census/ stating the counting rules below and the command.

2. Counting rules (apply exactly; they are the master's published rules)
   - Read each block's own lead, bullets, prose, tables and exceptions. Split a claim when one outcome can fail while another still holds; keep conditions with the outcome they qualify. Count a restatement once at its owner and point aliases to it. Do not count Sources/Provenance/Findings metadata.
   - full: the formal rule distinguishes the required cases through the stated observation, directly or by documented composition. A model label, code locator, native observation, binding AGREES count, test pass or successful proof without the necessary property does not make an obligation full. partial: the model represents some of the cases or stops before the reader, or takes the decision as an input. absent: no formal rule represents it. unassessed: not yet judged.
   - Design check is separate from representation: a modeled counterexample (witness) of an as-built violation is `refuted` with representation full when the witness reaches the stated observation; a proof over all sizes is `proved`; an explorer or finite-domain result is `bounded` with its domain. A failed/timeout run is `unchecked`.
   - Reuse an existing grade only when its statement, model, premises and evidence still apply: check that the cited theorem/witness still exists and its latest receipt is fresh (check_evidence.py), and that the coverage.md wording matches the current block text. Note moved blocks (the reorganization) keep their IDs; the crosswalk's "new" label for moved blocks is a relabelling artifact, not a new statement.
   - Parents: identify what the parent promises beyond its children. If it only restates them, record zero additional obligations after checking each owner. Otherwise list the child properties and either document why they jointly entail the parent obligation under compatible premises (inherited coverage) or keep the parent obligation open with the case where every child holds and the parent fails. An ordering, shared-state or completion guarantee across children can be missing while each child passes.
   - Check current models even when a block has no registered Verus link: search models/*/manifest.json ontology_ids, NOTES.md, coverage.md and crosswalk/decision-links.tsv for the block id and for the behaviour.
