# Reader self-check — the public cases where the two arms differed

**A self-check by the consolidating session, not an independent review** (that is pending; see [HANDOFF](HANDOFF.md#10-independent-review-pending)). For each public case where the guidance arm and the playbook arm scored differently on either axis (`public-baselines.tsv`: M02, M03, M07, M09, M11, M12, M13, M14, M16, M21, M23, J01, J02, J04, J05, J07, J08), the two outcomes below are written from `.g5/ontology` alone, with the blocks used. Where a block lacked a condition while writing this, the block was fixed first (noted). Formal support is not graded here.

| Case | Outcome 1 (from the ontology) | Outcome 2 (from the ontology) | Blocks used | Fixed during the check |
|---|---|---|---|---|
| M02 | A key used only by a refused commit stays free, so a later commit with it succeeds. | A retry of a committed changeset with the same key and fingerprint returns the original revision, marked replayed, and appends nothing. | `ledger.idempotency` | no |
| M03 | Two writes of one property in a changeset keep both records (prior and new each time) and the property shows the last value. | The first failing change stops the commit and rolls back every earlier change: no revision, record or content change remains. | `ledger.commit` | Tier 1 lift |
| M07 | A window that fits the first page is answered and freed inside the opening call: one round trip, no close call; at a later done page the server frees the handle and the reader sends no close. | Closing mid-read sends one close call and frees the handle; a second close sends nothing and the reader returns no more events. | `temporal.window.paging.release` | new block |
| M09 | A store that was never stamped is stale even while the token is zero (an unset stamp means "not known", never zero). | A store stamped at zero is current while the token is zero, and becomes stale when the token moves. | `structure.rebuilt.stamp` | new block |
| M11 | Two edges of one type between the same two nodes are two one-hop rows; the ID shortcut repeats the target once per edge. | `count()` counts both; asking for distinct answers folds them. | `structure.multigraph.count` | Tier 1 lift |
| M12 | The weighted search returns a path with the lowest total cost even when it has more hops than another path. | When no path joins the two nodes it returns no row (and a failed search raises instead). | `algorithms.op.paths.weighted` | new block |
| M13 | A writer that declares a different model for a table that already records one is refused; vectors of two models never share a table. | A write naming a model key goes to that model's own route for its graph, so another graph's write is unaffected. | `search.embedding.other_model` | no |
| M14 | A query vector whose width differs from its route's is refused before any search statement runs, naming both widths. | A graph and model with no route answers empty before any width check, never a width error. | `search.embedding.width`, `search.routes.no_fallback` | Tier 1 lift |
| M16 | Nothing is declared while the callback classes, the schema's procedure class, the edge key column or the graph columns are missing; setup skips with a reason. | Once they exist both indexes are declared (edge first); an index already declared is left alone, and a plain index of the same name is replaced. | `structure.adjacency.declare` | new block |
| M21 | Changed parameters are a different cache key, so a different answer is computed and cached. | A repeated call with unchanged parameters and graph returns the cached answer; nothing stale is returned. | `algorithms.cache`, `algorithms.cache.token` | no (formal support is a reviewed design; see the block's `Verus:` line) |
| M23 | The unindexed edge load first adds each edge's two end nodes to the loader's graph. | A row IRIS refuses for a reason other than a repeat stops the load with a bulk load error naming the rows inserted first; never "zero inserted". | `install.bulk_load.loader` | Tier 1 lift |
| J01 | A restore creates each routed table at the width the archive records (not the restoring engine's width), and the width-checked search then reads it. | Node and routed vectors are matched on graph and node, so each graph's restored table holds only its own rows. | `install.snapshot.routes` | new block |
| J02 | The temporal subtrees saved are derived from the store plan the restore uses, so the event comes back. | A restored temporal event answers a window read, not only a row count. | `install.snapshot.temporal`, `temporal.window` | new block |
| J04 | A second connection reuses a cached answer computed by the first while the graph is unchanged (the cache serves every connection). | After a committed graph write moves the token, the next call recomputes before returning. | `algorithms.cache`, `algorithms.cache.token`, `structure.rebuilt.token` | no |
| J05 | Two commits sent at once with the same key and payload make one revision (commits run one at a time). | The same key with different operations fails with an idempotency conflict. | `ledger.idempotency`, `ledger.commit.serial` | no |
| J07 | Before the edge index is built, every triple with temporal events but no row gets its marked row. | Without the edge key column, setup defers the declaration and a later setup declares it. | `structure.adjacency.declare` | new block |
| J08 | In job mode a new shape is answered by the interpreter while a background job compiles it. | A failed compile leaves the interpreter answering (compiling never makes a read fail) and is not retried until the compile stamp changes. | `query.compiled.modes`, `query.compiled.fallback` | no |

Two cases where both arms scored the same but the ontology changed are also answerable now: M06 (`temporal.window.sources`: omitted reads every source, an empty list reads none) and M08 (`temporal.window.paging`: an empty page not marked done does not end the read; `temporal.window.paging.release`: a failed page raises after one close call), and M17 and M18 (`adapters.embedded.no_data`, `query.values.relationship_text`), which no ontology answered before.
