## Architecture review conditions

Necessary chain: raw registry/cache -> selected decoded route -> raw query parser
and catalog parser -> comparison/dtype/error ordering -> every actual scoring
attempt -> final typed reader. Cache uses raw returned rows and own timestamp
writes, not an assumed always-current route. Separate Build action shares routing
but preserves validation/dependency order and its own no-route refusal. No padding
or truncation may change the literal bind; source binds literal text unchanged.

Track at least RegistryRead, CatalogRead, SeedRead, SqlScoreAttempt,
EmbeddedScoreAttempt, ClientVectorRead, ClientKernelAttempt/Success, Build,
AddBatch, Finalize, Info, Return/Raise. A SQL observer must recognize actual
statement/selected fields; substring EMB also matches embedding_registry and is
not a valid vector-read counter. Count attempted effects on fault paths. Registry
rows are materialized before close; do not generalize cursor cleanup: primary
kg_KNN_VEC has no explicit close here, optimized DBAPI closes only on success,
client has finally-close, and IVF admission does not close every opened cursor.
These are source correspondence boundaries, not new issue adjudications.

Fresh distinguishing cases beyond the inherited happy paths include unexpired
cached route with current non-30 backend fault (hit must not read/raise), exact
TTL expiry then same fault (must read/raise), semantic row.tableNone cached as a
decoded row, unknown physical width versus heuristic VARCHAR4000, embedded
entityIDNone versus DBAPI entityIDNone, and malformed Info after build effects.
The final theorem may be narrower, but these cases must remain visible/unassessed
rather than turned into impossible source inputs or fixture success by fiat.
