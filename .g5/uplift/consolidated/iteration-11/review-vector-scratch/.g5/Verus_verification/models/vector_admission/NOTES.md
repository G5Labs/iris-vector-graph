The package models the ordinary node-vector read workflow, beginning with raw registry rows, raw typed fields, raw query characters and metadata strings. It does not take a readable bit, selected table, query length, mismatch bit or final answer as an input. `resolve` filters raw graph/model/kind records, stably selects the first lowest-preference well-shaped row, decodes dimension/dtype and writes only decoded rows into its own cache. The tuple key includes registry/schema, normalized graph/model and kind. A readable named miss is empty; unavailable registry / all-short rows retain the source's compatibility legacy exception. A decoded row whose table is None is still cached and produces empty before width/dtype work. Bad dimension conversion precedes cache insertion. Other registry errors are not absence.

The cache relation includes its own timestamp write, separate from the next lookup timestamp, exact strict `elapsed > TTL` expiry, TTL0 bypass, read counts and local invalidation. Time is mathematical integer ticks preserving the source comparisons; binding uses exact finite float replies (including30/30.001 and distinct lookup40.001/store45). This is not a theorem about binary64 clocks, clock drift, database isolation or concurrent DDL. The miss->raw publication theorem derives the second result from a new raw row; the binding additionally runs actual `_read_route` / `resolve_route` / `_create_route` over inherited local SQL fakes. It does not prove that writer's DDL/transaction algorithm. The earlier possible cached-absence forecast was refuted by source and actual tests and remains a miss/nonbug. Positive rows can hide replacement/backend errors until expiry.

`json_width.rs` is a raw-character stack/lexer, including nested arrays/objects, quoted/escaped strings and Unicode escapes, numeric syntax, booleans/null and Python JSON NaN/Infinity/-Infinity spellings. Its width is the outer array's element count, not a comma count or numeric-element count. Python Unicode `strip` characters are represented separately from JSON interior whitespace. `parser.rs` retains a smaller numeric-array grammar for the client CSV shape fragment and raw ASCII integer fields. `catalog.rs` derives LEN comma/control-byte and INFO_SCHEMA heuristic widths from raw cells, including the source's VARCHAR4000/digit-join result and lower/upper fallback order. A nonzero recorded width wins; zero/absent falls through catalog; no comparable width and invalid literal parsing defer to providers. Catalog query/schema/class resolution and identifier validation are ordinary valid-identifier provider premises. Heuristic metadata is not physical VECTOR truth. Unicode decimal digits, unusual regex whitespace, arbitrary driver `$LIST` representations and malformed class/table identifiers are outside the correspondence fragment unless separately observed.

The search relation chooses actual Primary -> Optimized -> Client calls, with rank2/1/0 termination rather than a runtime budget. A derived phase constructor carries the original registry, graph and model through every call and fixes kind=node; only raw provider replies and clock samples vary by phase. Direct optimized/client entry points perform their own resolution and preflight. Primary dtype selection/uppercase precedes width. The trace distinguishes primary, embedded and DBAPI score attempts, seed reads, catalog/registry reads, client vector reads and every client kernel attempt; the terminal outcome records return or error. Primary -257/message-width refusal diagnoses and raises before fallback. Generic primary failure enters optimized embedded SQL, then DBAPI, then the client. Embedded readers drop raw IDNone before float conversion; primary/DBAPI readers retain it. Primary requires exactly two fields; optimized indexed readers admit extra fields. Numeric SQL/numpy results are named raw provider replies, then the actual typed readers decide outputs. No cosine, ANN recall, floating-point optimality or native provider correctness theorem is claimed.
