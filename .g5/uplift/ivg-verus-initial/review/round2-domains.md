### Graph scope and keys

- E-GS1 (D, ADR-0003, GraphKey.cls:41-75): the `^KG` key and the ledger key both derive from the name; `"0"` and control characters are refused, `$Char(0)` is stripped as SQL padding. A wrong key reads nothing and never falls through to the default graph. The interned snapshot `^NKG` has no graph dimension (CONTEXT "Interned snapshot"); `Adjacency.Put` interns named-graph edges into it too (Adjacency.cls:95-107), so `^NKG` answers are the default graph's only while no named graph has an edge (KNOWN_ISSUES "The ^NKG algorithm procedures raise").
- E-GS2 (D, CONTEXT "All-graphs read/write"): a read that names no graph is the union of per-graph answers; SET/REMOVE/DELETE touch the bound element's own graph only; CREATE and MERGE go to the default graph.

### Structure, degree, version token, algorithm cache

- E-ST1 (D, ADR-0008/0011): where the adjacency index is declared, every row write (engine, SQL, Cypher DML, ledger, bulk) changes `out`/`in` in the row's transaction; no adjacency entry without a row. Where it is not declared, only engine writers and a rebuild keep it current (two operating modes must both be representable).
- E-ST2 (D, ADR-0010/0012, Adj.cls:52-90): degree = count of `out` entries with `"#"` multiplicity. The cache entry `(gen, count)` is served only while gen is current; a reader stores only if its exclusive no-wait probe of `^IVG.AdjW(g)` succeeded, no lock-less write mark `^IVG.AdjNoLock(g)` exists, and gen did not move. Outcome-changing cases: rolled-back write (gen over-bumps; the store must not keep a count including the uncommitted edge), a writer that could not get the shared lock in 5 s (4.7.0 row 17: writes anyway and marks the graph), erase of a source (gen killed, then restarts at a value an old entry carries: Adj.cls:44-47 re-reads gen after the store), reader inside the writer's own transaction (allowed to cache; rollback takes it back), read-only database (`<PROTECT>` swallowed, count returned).
- E-ST3 (O, Adj.cls:184-218): the whole-graph stamp `degw = __version` makes every entry valid without a gen read and an absent entry mean zero; any adjacency write moves `__version`. Every writer that changes `out` must therefore move `__version` before its effect can be relied on.
- E-ST4 (D, CONTEXT "Graph-Version Token", AlgoCache.cls): the token is read before computing; a cached algorithm answer is valid only while the token is unchanged; the token never falls and is never reused. Things that change an algorithm's answer without moving `__version` are bypasses: node rows with no edge (handled by putting the loner list or a node-table token in the key: iris_sql_store.py:2362-2381), weight changes (`Adjacency.PutShadow` on an existing triple refreshes the weight without moving gen or `__version`, Adjacency.cls:121-139), and stores read by an algorithm that are not `^KG` (`^NKG` rebuilt separately). Snapshot restore writes the archive's `__version` over the live one for the duration of the import, then sets `max(floor, restored)+1` (snapshot.py:48-58 plus ArnoAccel.BumpVersion): the token can fall transiently during a restore.
- E-ST5 (D, spec 234, GraphMode.cls): in a multigraph a parallel edge counts towards degree; outside it a second identical relationship adds nothing. Turning the mode off is refused while any triple has two edges; the check and the kill are not atomic against a concurrent parallel-edge writer (GraphMode.cls:25-41).

### Temporal edges

- E-T1 (D, ADR-0009/0015): a temporal write of a structural predicate asserts a marked structural row (and nodes) in the same graph; an explicit `create_edge` (and `bulk_create_edges`) adopts it and clears the marker; Cypher CREATE/MERGE of a marked triple does not adopt (open item recorded in ADR-0009's amendment). A temporal-only predicate writes the temporal globals only.
- E-T2 (D, ADR-0009 amendment): when the last timestamp of a triple goes (DeleteTemporalEdge, PurgeRawBefore, PurgeBefore), its row goes while still marked; rows before raw entries, so a failed purge is finished by re-running it. Nodes stay unless `retire_bare_nodes`.
- E-T3 (D, CONTEXT "Collision", TemporalIndex.cls:80-131): mode insert at occupied coordinates changes nothing and is counted (BulkInsertCounts reports it; single `InsertEdge`/`create_edge_temporal` returns 1/True either way, so a single-edge caller cannot see it). Mode update replaces tout/tin and edgeprop but re-runs the aggregate increments: `bucket`, `tagg count` and `sum` count the same coordinates twice (TemporalIndex.cls:83-86 has no early return for update; the docstring calls this "does not adjust").
- E-T4 (O): no transaction or lock spans a temporal write or a purge. `WriteStores` writes `tout`, `tlast`, `tin`, `bucket` before `AssertTemporalRow`; a refused row leaves those written. `RetireExpired` decides which triples have no surviving timestamp and then retracts their rows with no lock against a concurrent `InsertEdge` of the same triple: an insert landing between the survivor walk and the retract leaves a live timestamp with no structural row (competing writers).
- E-T5 (D, ADR-0015): the opt-out registry is read per batch (BulkInsert) or per edge; the purge skips registered predicates (old rows remain until `DropRows`); `DeleteTemporalEdge` does not consult it; drop/backfill need the adjacency index.
- E-T6 (O, temporal.py:334-389): on an engine built with `temporal_structural_rows=True` the Python delete reads the marker, deletes the timestamp, then calls `delete_edge` when no timestamp survives; an explicit `create_edge` landing between the marker read and the delete is removed (check-then-act).

### Search

- E-S1 (D, ADR-0007, BM25Index.cls:442-513): schema-2 Insert/Delete run under `^BM25Idx(name,"lock")` in a transaction with plain Set; a schema-1 or upgrading index refuses writers (rechecked under the lock); Upgrade sets the flag, then takes the lock, flips `schema` last and is re-runnable. Search is unlocked and reads uncommitted state.
- E-S2 (O, BM25Index.cls:97-171): `Build` kills and rebuilds the whole index with no lock and no transaction, and sets `N`, `totalLen` at the end; an Insert running during a Build sees "no N" (a new index), writes under its lock, and Build's final `Set N` overwrites the count: `df` and `N` disagree afterwards. Competing writers Build vs Insert/Delete/Upgrade are a case a BM25 model must represent or exclude explicitly.
- E-S3 (O): nothing maintains a BM25 index from node property writes, node deletes or erasure; `^BM25Idx` is in no `GraphStores.Inventory` entry and the Eraser does not touch it (grep), so an erased graph's node ids and terms stay searchable. `bm25_insert` takes any doc id, with no graph check against the index's recorded graph.
- E-S4 (D, CONTEXT "Common-term cutoff"): terms over the df fraction are skipped; if all known terms are over it, the rarest is kept; unknown terms are neither skipped nor kept; the search reports skipped terms and the fallback.
- E-S5 (D, ADR-0005/0006, embedding_identity.py:180-241): registry identity is checked before every vector write; width and dtype in all four cells; model only when both sides know one; an unclaimed table is claimed by the first known-model writer (atomic: the registry row's key refuses a second route row, embeddings.py:509-523). An undeclared writer is not model-checked against a claimed table (cell "offered unknown / recorded known").
- E-S6 (D, KNOWN_ISSUES): a named graph's vectors live in its own route; the SQL procedures read only the default graph's (refused with -149 since 4.6.0); `kg_RRF_FUSE` answers [] when a leg fails (4.7.0 known issue).

### Platform

- E-P1 (D, ADR-0016, schema.py:2212-2312, schema_name.py:184-205): the first `initialize_schema()` records the IVG Schema; a later engine on another name is refused; the record is written after the whole setup with no compare-and-set, so two first setups racing on a fresh namespace both pass the read and the last write wins; an interrupted setup leaves no record (KNOWN_ISSUES "After an interrupted setup").
- E-P2 (D, ADR-0014, Gen.cls:61-107): a compiled plan runs only when its entry's shape and stamp equal the running ones and status is "ok" and the class name is this hash's; pending for under 120 s or failed means interpreted; a deploy drops everything. The entry key is a 32-bit CRC of the shape; a colliding shape overwrites the entry and recompiles the same class name, and a process that checked the entry before the recompile can run the other shape's walk (narrow race).
- E-P3 (O): strict ledger mode skips the Python temporal mirror (temporal.py:304) but `InsertEdge` still asserts the marked row inside IRIS when the index is declared, so strict mode does not keep temporal SQL rows out of the ledger-bypass set.

## Coverage findings

- **R2-1: a BM25 delete issued during a Build is lost, today and under the proposed repair.** `Delete` returns 0 before it takes the lock when `cfg N` is absent (BM25Index.cls:496-499), and `Build` sets N only after its scan (:160). A `bm25_delete` that runs while a Build is in flight therefore answers False ("not in the index"). If the Build's scan has already flushed that document, the Build then publishes it. No artifact represents this: bug-srch-003 covers counter inconsistency only, and the search model's `DelBegin` lets the no-N branch return without effect. The proposed repair ("Build and Drop take the index lock") does not close it, because the N test stays in front of the lock. Under `locked_build()` my scratch witness `r2_witness_locked_build_loses_delete` verifies: the repair invariant `winv` holds at every step, yet the deleted document is in the published index. The coverage row's claim that the repair "covers Build/Drop inside an Insert or Delete" is therefore too broad. The repair proves counter consistency, not that a committed delete takes effect.
- **Gap list honesty.** The domain gap lists match what I found unmodelled: `degw`/AllWarm, `^NKG`/`^ArnoKG`, `USE GRAPH` confinement, window reader and `tlast`, min/max/HLL, fusion, quarantine, IVF/PLAID erasure, `off` mode, and all of FHIR and algorithms routing. Each is listed with a finding or question. The only omission in my scope is R2-1.
- **Statements without a model or observation that matter.** `structure.rebuilt.token` (every adjacency change moves the token) is honestly marked Assumed, and test_236_* were skipped. See R2-5 for a code counterexample in the non-indexed mode.

## Fidelity findings

- **R2-2: the phased purge decide is narrower than the product.** `doomed_set` takes only triples whose row exists and is marked at decide time (`temporal.rs:689-691`, via `purge_doomed`). `RetireExpired` puts every structural candidate with no surviving timestamp into `^||IVG.TPurge`, whether or not it has a row (TemporalIndex.cls:956-1013). `RetractTemporalRows` then tests the marker at its DELETE (Adjacency.cls:674). So a triple that had a timestamp in range but no row at decide time loses the marked row that a concurrent writer asserts before the retraction. Production can reach that starting state: the ADR-0015 opt-out/opt-in window (fwd exception (c)) or bug-tmp-001's throw. Shipped model: `r2_witness_model_keeps_row_created_after_decide` verifies (the row survives). Product-faithful decide: every one of the 104 original obligations still verifies, including `lemma_phased_purge_serial`, and `r2_witness_faithful_decide_drops_row_created_after_decide` proves `!fwd_ok`. The model therefore hides a race route that bug-tmp-011's repair ("per-triple lock or a re-check") must also cover. Abstraction removed behaviour; no obligation depends on that.
- **R2-4: the temporal statistics rule cannot see a zero counter.** L1 `exact` compares `get0(bucket, k)` (temporal.rs:811-815), so a bucket node holding 0 counts the same as an absent one. The product kills at zero on purpose: "A zero counter is not neutral" (TemporalIndex.cls:355-357). `FindBursts` lists every source present in a bucket, so with threshold ≤ 0 it reports a velocity-0 burst (:784-803). Native R5 and R6 left exactly such a node (`raw bucket=0`). With a faulty "keep zero counters" implementation, every L1 obligation still verifies; only one witness's journal assertion fails (Adversarial checks).
- **R2-5: `structure.rebuilt.token` is contradicted in the non-indexed mode.** The [I] block says every change to the adjacency index moves the token. `Adjacency.PutShadow` on an existing triple rewrites the `out`/`in` weight without bumping `__version` (Adjacency.cls:128-136), unlike `Reweight` (:340). `^ArnoKG` is validated only by `__version`. The cached algorithms (PageRank, PPR, WCC, CDLP) count multiplicity and do not read weights, so `^IVG.AlgoCache` is unaffected. Source reading only; non-indexed installs only.
- **Witness reachability.** I checked W-RACE-1/2/3, W-O1a/b/c, W-O2a and the forging witness W-O2b against the unlocked code paths; production can execute each of them. Status words in the domain rows match their receipts and observations. The exceptions are the stale "not run" texts in R2-3, which understate.
