# Decisions for the human: module 01 (install, schema, upgrades)

### HD-0101 Should an engine that cannot read the schema record be refused?
- Owner: human
- Question: spec 262 FR-006 says an engine whose schema differs from the namespace's record must be refused on first
  access. When the record cannot be read (a user without %Native_GlobalAccess, or any other exception), the engine
  logs a WARNING and skips the check, so an engine built for another schema may write into the namespace beside the
  recorded one and share its globals.
- Options: (a) keep failing open, as ADMIN_GUIDE section 3 documents; (b) refuse like a mismatch until the record is
  readable; (c) fail open for reads, refuse writes.
- Default the code applies today: (a). iris_vector_graph/engine.py:1859-1868; docs/ADMIN_GUIDE.md:500-504.
- Cited by: INS-Q3.10.

### HD-0102 Should setup save the schema record when the class deploy failed or was turned off?
- Owner: human
- Question: initialize_schema writes ^IVG.Deploy("schema") after any run that is not a preview, even when the deploy
  raised, a class failed, or auto_deploy_objectscript=False. From then on every engine is accepted by the first-use
  check, though the per-graph erase, the ledger and the adjacency index need the classes. The warning in the reply is
  the only signal.
- Options: (a) record anyway (today); (b) record only when objectscript_deployed is true and objectscript_failed is
  empty; (c) record, but mark the record incomplete so the first-use check names the missing classes.
- Default the code applies today: (a). iris_vector_graph/_engine/schema.py:2309-2313, 2578-2602.
- Cited by: INS-Q1.15.

### HD-0103 Are the files under sql/ part of the product?
- Owner: human
- Question: sql/ holds schema.sql (a pre-spec-227 schema with single-column keys and no graph_id), globals_schema.sql
  (an unqualified procedure and two stub triggers on Graph_KG.rdf_edges), graph_path_globals.sql and
  graph_walk_tvf.sql (unqualified procedures), migrations/000-002 (the 2025 NodePK migration) and procedures/
  kg_PageRank.sql (comments only). Setup runs none of them; the sdist ships them; scripts/deploy_production.py still
  runs sql/schema.sql and sql/operators_fixed.sql. The index of this uplift counts sql/ as product.
- Options: (a) keep as historical samples, marked as such; (b) delete them and the scripts that load them; (c) bring
  them in line with the IVG Schema.
- Default the code applies today: shipped in the sdist, unused by setup.
- Cited by: INS-Q11.2; related finding F-0105.
