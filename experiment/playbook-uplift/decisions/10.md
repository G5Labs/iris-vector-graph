# Decisions for the human: 10 Graph algorithms and traversal

### HD-1001 What should `random_walk` answer, and over which graph?
- Owner: human
- Question: `random_walk` needs the Arno library and answers `[]` without it, although the walk it calls
  (`NKGAccelTraversal.RandomWalkJson`) is ObjectScript; with the library it walks `^NKG`, every graph merged (F-1002).
  No spec states its intent.
- Options: (a) always walk the default graph's `^KG` in ObjectScript, library or not; (b) keep it library-only but
  refuse once a named graph has edges, as the `^NKG` procedures do; (c) add `graph=` and walk that graph's `^KG`;
  (d) retire it.
- Default the code applies today: `[]` without the library or on any failure; with it, a walk over `^NKG` with no
  graph check.

### HD-1002 Should label propagation say when its labels did not settle?
- Owner: human
- Question: `kg_CDLP` returns the last round's labels after `max_iterations`, and labels often swap every round
  (`docs/COMMUNITIES.md:192-208`); `kg_WCC` and `eigenvector_centrality` raise when they do not converge.
- Options: (a) raise like WCC; (b) answer and flag non-convergence (a `_meta` row, a warning); (c) keep it silent and
  documented.
- Default the code applies today: (c), the last round's labels with no sign.

### HD-1003 Should the shortest-path routines refuse a direction they do not walk?
- Owner: human
- Question: `TraversalPaths.ShortestPathJson` walks only `"out"` and `"both"` and answers no path for anything else;
  `ShortestLength` reads any value but `"both"` as `"out"`. The store and query callers guard (they turn `"in"` round),
  but both are callable class methods. `DijkstraJson` and `DijkstraCost` refuse through `CheckDirection`.
- Options: (a) call `CheckDirection` in both and accept `"in"` by walking from the far end; (b) keep the guard at the
  callers and document the class methods as internal.
- Default the code applies today: (b), undocumented.

### HD-1004 How many nodes should global PageRank list?
- Owner: human
- Question: the ObjectScript owner stops at 10,000 rows; the native reader lists every node (F-1003). The method takes
  no top-k, and the docs promise neither.
- Options: (a) every node on every route; (b) 10,000 on every route, documented; (c) add a `top_k` with a stated
  default.
- Default the code applies today: 10,000 rows from the owner, every node from the native reader.
