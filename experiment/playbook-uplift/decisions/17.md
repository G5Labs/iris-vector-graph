# Decisions: module 17 (operations and runtime)

Intent the code and the documents leave open. Each names the default the code applies at the pin.

### HD-1701 Should the SQL adapter's pass-through refuse a write when called read-only?
- Owner: human
- Question: `IRISGraphStore.execute_sql(sql, params, read_only=True)` and the `GraphStore` protocol carry a
  `read_only` flag, but nothing reads it (`iris_vector_graph/stores/iris_sql_store.py:1522-1554`). Is the flag a
  promise (refuse INSERT/UPDATE/DELETE/DDL when True) or a leftover?
- Options: (a) enforce it: refuse a non-SELECT statement with a clear error before it runs; (b) remove the parameter
  from the protocol and the adapter; (c) keep it as documentation only and say so.
- Default today: the flag is ignored; any statement runs, and a failure comes back in `IVGResult.error`.

### HD-1702 Should the HTTP client resend a write query after a server error?
- Owner: human
- Question: `IVGClient._post` retries `POST /api/cypher` up to `max_retries` (3) times on a 5xx, a connect error or a
  timeout, with 0.5 s, 1 s backoff (`iris_vector_graph/sdk.py:209-228`). A Cypher `CREATE` whose first attempt
  committed on the server and then failed to answer (a 5xx after the commit, or a timeout) is sent again.
- Options: (a) retry only reads (the client cannot tell; the server could mark replies); (b) retry only connect errors,
  never 5xx or timeouts; (c) keep retrying everything and document that writes must be idempotent (MERGE) or carry a
  ledger retry key.
- Default today: every `execute_cypher` is retried, reads and writes alike.

### HD-1703 Should the SQL adapter's capability list say what this namespace can run?
- Owner: human
- Question: `IRISGraphStore.capabilities()` returns `_FULL_CAPABILITIES`, every algorithm `True`, whether or not the
  ObjectScript classes are deployed or the accelerator is loaded; only the `*_arno` keys vary
  (`iris_vector_graph/stores/iris_sql_store.py:29-52`, `:2991-3000`). The engine uses it to choose store calls over
  Python fallbacks.
- Options: (a) answer from what is deployed (classes compiled, procedures present); (b) keep "what the code supports"
  and point callers at `status()` for what is installed.
- Default today: (b), undocumented.

### HD-1704 Should the low-level vector helper refuse a vector of the wrong width?
- Owner: human
- Question: `dbapi_utils.normalize_vector` pads a short vector with zeros, truncates a long one and turns NaN/Inf into
  0.0 (logged only under `IRIS_VECTOR_DEBUG`); `insert_vector` then writes it (`iris_vector_graph/dbapi_utils.py:29-98`).
  The engine's own writers refuse a width mismatch (ADR-0006, `EmbeddingIdentityConflict`). Which rule do the public
  helpers follow?
- Options: (a) refuse a width mismatch and non-finite values, as the engine does; (b) keep coercion and document it as
  lossy.
- Default today: silent coercion.

### HD-1705 Should server start refuse to listen on every address without an API key?
- Owner: human
- Question: `deploy/README.md:86` says the server refuses `auth: none` with `host: 0.0.0.0` unless `--force-no-auth`;
  `docs/ADMIN_GUIDE.md` section 5 says that with `IVG_API_KEY` unset the server asks for no key and listens on
  `0.0.0.0:8200`. The code does the latter (`iris_vector_graph/cli.py:419-441`, no `--force-no-auth` option).
- Options: (a) implement the refusal (bind 127.0.0.1 or exit unless a key or an explicit flag); (b) keep the open
  default and correct deploy/README.md.
- Default today: open on every interface, no key (see finding F-1709).
