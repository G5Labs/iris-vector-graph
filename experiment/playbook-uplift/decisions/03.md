# Decisions for the human, module 03 (direct writes)

Cited from `ontology/03-writes.md` as `open:HD-03kk`.

### HD-0301 Does ledger strict mode cover the standalone bulk loader?
- Owner: human
- Question: strict mode refuses the engine's direct writes (docs/USER_GUIDE.md:1107-1121) through a check in each
  engine method (`ledger_check`, iris_vector_graph/_engine/ledger.py:72-79). `iris_vector_graph.bulk_loader.BulkLoader`
  takes a DB-API connection, not an engine, and has no such check (bulk_loader.py:56-78, 252-272, 380-402), so it writes
  nodes, labels, properties and edges with no ledger record while strict mode is on. Is that intended?
- Options: (a) the loader is an operator tool outside the ledger's guarantee, and the USER_GUIDE says so; (b) the
  loader reads `Graph.KG.Ledger.Meta()` and refuses in strict mode, as `LedgerGuard` does; (c) the server refuses the
  writes (a guard in the SQL path), which would also cover plain SQL.
- Default the code applies today: the loader writes in strict mode (finding F-0301).

### HD-0302 May a direct edge delete remove an edge row that a temporal edge still implies?
- Owner: human
- Question: ADR-0009 says every temporal edge implies a structural edge for its triple, kept as a marked row that only
  the temporal side removes (CONTEXT.md:66-73). `delete_edge(s, p, o, graph=g)` deletes the triple's rows whether or
  not they are marked (iris_vector_graph/_engine/nodes_edges.py:1429-1433), leaving the temporal events with no
  structural edge.
- Options: (a) delete the row and leave the temporal events (today); (b) refuse while the triple has temporal events
  and the row is marked; (c) delete the row and the triple's temporal events together; (d) leave a marked row alone and
  delete only an explicit one.
- Default the code applies today: (a).
