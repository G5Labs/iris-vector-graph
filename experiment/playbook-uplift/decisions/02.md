### HD-0201 What does a Python read with no graph argument read?
- Owner: human
- Question: the USER_GUIDE says Python methods that read take `graph=` and, omitted, mean the default graph, never
  every graph (docs/USER_GUIDE.md:466-467). Several readers take no `graph=` at all and read every graph:
  `get_node_ids_by_label`, `get_node_ids_by_property`, `get_property_pairs`, `get_property_values`,
  `property_value_exists`, `get_node_ids_like`, `count_subjects_with_property`, `nodes_exist`
  (iris_vector_graph/_engine/nodes_edges.py:760-966, 2590-2625). Their docstrings say "all graphs" or "not
  graph-scoped". Which rule holds?
- Options: (a) every reader takes `graph=`, omitted is the default graph (the USER_GUIDE rule); (b) an omitted graph
  reads every graph and each row says its graph (the Cypher all-graphs rule, CONTEXT.md:38-42); (c) keep the id-only
  readers all-graphs and document them as an exception in the USER_GUIDE.
- Default the code applies today: (c) without the documentation; and `get_nodes_by_label` / `get_nodes_by_property`
  join every graph's ids with the default graph's node data, which is finding F-0206 whatever is decided.

### HD-0202 In a multigraph, does a direct edge delete remove one parallel edge or all of them?
- Owner: human
- Question: `delete_edge(s, p, o, graph=g)` deletes every row of the triple in `g`
  (iris_vector_graph/_engine/nodes_edges.py:1429-1433). Spec 234 gives the direct API `create_edge` a multigraph
  rule (FR-007) and Cypher `DELETE r` a per-edge rule (US1 scenario 2), but says nothing about `delete_edge`.
- Options: (a) all parallel edges of the triple (today); (b) refuse with an ambiguity error when the triple has more
  than one edge, unless an edge key or edge id is given; (c) add an `ekey=` / `edge_id=` argument and keep (a) as the
  default.
- Default the code applies today: (a).
