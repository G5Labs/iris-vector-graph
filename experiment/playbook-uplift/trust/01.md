# Premises of module 01 (install, schema, upgrades)

Each premise is something setup relies on about IRIS, the driver or the test harness. None was checked live by this
builder. "Source comment" means the product's own code records a measurement that this uplift has not repeated.

### P-0101 The %AI classes exist only on AI Hub builds of IRIS
- Statement: IRIS Community 2026.1 has embedded Python and has no %AI package (%AI.MCP.Service, %AI.Tool, %AI.ToolSet,
  %AI.Policy.ConsoleAudit), so Graph.KG.MCPService, Graph.KG.MCPToolSet and Graph.KG.MCPTools cannot compile there and
  setup skips them with their reasons.
- Used by: INS-P4.5, the class set cells, the select_classes skip rule (iris_vector_graph/_engine/class_deploy.py:78-106).
- Evidence so far: docs/ADMIN_GUIDE.md:353; tests/e2e/test_470_setup_compiles_every_class_e2e.py (live, opened, not
  run). The orchestrator's preflight log `preflight/redaction-community.log` (not a run of this builder) shows
  initialize_schema on Community 2026.1 deploying 66 classes and skipping exactly these 3.
- Check: live (setup on $IVG_TEST_CONTAINER, read status["objectscript_skipped"]).

### P-0102 A failed class in a CompileList does not stop the others
- Statement: %SYSTEM.OBJ.CompileList compiles every class of the list it can even when one fails, so a second pass
  finds the dependents compiled.
- Used by: INS-P4.15, INS-T4.9 (the retry and one-by-one fallback in upload_and_compile).
- Evidence so far: source comment at iris_vector_graph/_engine/class_deploy.py:278-292 (Build 154, MCPToolSet).
- Check: live (compile a list holding one class that cannot compile; count the others compiled).

### P-0103 Schema names are not case-sensitive; class package names are
- Statement: IRIS SQL treats `ivgalt` and `IVGALT` as one schema, while class and package names are case-sensitive.
- Used by: INS-B2.5, INS-P2.17, the marker probe for the name and its upper-case form (schema_name.py:231-235).
- Evidence so far: specs/262-ivg-owned-sql-schema/spec.md:205-206; tests/e2e/test_262_record.py
  ::test_a_record_compares_without_case (live, not run).
- Check: live.

### P-0104 A schema's class package is its name with underscores turned into dots
- Statement: IRIS compiles a schema's tables and DDL functions into the package whose name is the schema name with `_`
  replaced by `.` (Graph_KG gives Graph.KG).
- Used by: INS-D5, INS-P2.18, INS-X2.4, INS-X2.6 (package-clash refusal), the source rewrite.
- Evidence so far: specs/262-ivg-owned-sql-schema/research.md (R2).
- Check: live (CREATE TABLE MY_APP.t, read the class name).

### P-0105 IRIS names the missing privilege in its error text
- Statement: a DDL statement refused for want of a privilege fails with SQLCODE -99 and text such as "User X does not
  have %CREATE_TABLE privileges".
- Used by: INS-X1.5, INS-P12 (missing_privilege in schema_name.py:119-130).
- Evidence so far: tests/unit/test_262_setup_privilege.py (on recorded text, not live).
- Check: live (setup as a user without %CREATE_TABLE).

### P-0106 The upstream test session deploy compiles every class and fails on IRIS Community
- Statement: the session fixture in tests/conftest.py (_deploy_objectscript, lines 215-262) loads and compiles every
  class under iris_src/src one at a time with no skip rules, before the tables exist, and raises when any fails. On IRIS
  Community it fails for the MCP classes, which need %AI, and for classes that need a table or a generated class first.
- Used by: INS-P4.16, finding F-0108; every live suite that uses the fixture on Community.
- Evidence so far (orchestrator observations, not runs of this builder): `preflight/redaction-native.log` shows the
  fixture failing for 5 classes (MCPService, MCPToolSet, MCPTools, NKGAccel needing NKGAccelLoader, TraversalBuild
  needing Graph_KG.rdf_edges); the orchestrator's unit run saw 86 setup errors in
  tests/unit/test_203_tck_regressions.py for this reason. The orchestrator's `run-community-redaction.py` replaces the
  fixture's deploy with initialize_schema().
- Check: run (the upstream suite with and without that replacement).

### P-0107 CREATE OR REPLACE recompiles the routine's class and drops cached queries
- Statement: re-running `CREATE OR REPLACE FUNCTION|PROCEDURE` on an unchanged routine recompiles its class and
  discards the cached queries that call it.
- Used by: INS-P5.9, INS-B5.1 (why the routine record skips unchanged routines).
- Evidence so far: source comment at iris_vector_graph/routine_record.py:1-8 (4.6.0 R133).
- Check: live (count cached queries before and after a rerun).

### P-0108 IRIS keeps routine bodies and view queries in its catalog
- Statement: INFORMATION_SCHEMA.ROUTINES.ROUTINE_DEFINITION holds a function's body and INFORMATION_SCHEMA.VIEWS
  .VIEW_DEFINITION a view's query, in a form that matches the shipped DDL once white space is squashed.
- Used by: INS-P7.10, INS-B7.3 (which legacy objects are the product's).
- Evidence so far: source comment at iris_vector_graph/legacy_text.py:10-20, measured on 2026.3; not stated for
  Community 2026.1. If 2026.1 left them empty, every legacy function there would read as not the product's and be kept.
- Check: live on Community 2026.1.

### P-0109 A schema EXECUTE grant is listed once per routine with no GRANTED_VIA
- Statement: %Library.SQLCatalogPriv SQLAllPrivileges lists `GRANT EXECUTE ON SCHEMA` once per routine with
  GRANTED_VIA null, unlike a schema SELECT, which shows "Schema Privilege".
- Used by: INS-P6.15, INS-B6.4 (_EXECUTE_HELD_VIA in legacy.py:367-371).
- Evidence so far: source comment, measured 2026-11-07 on 2026.3.0AI.113.0.
- Check: live on Community 2026.1.

### P-0110 A REVOKE without AS removes only the current user's grants
- Statement: `REVOKE ... FROM x` removes only grants the current user made and answers SQLCODE 100 with no error for
  the others; `AS grantor` is needed.
- Used by: INS-P6.16, INS-B6.9 (revoke_legacy_arno revokes AS each grantor).
- Evidence so far: source comment at iris_vector_graph/_engine/legacy.py:539-541 (4.6.0 R147).
- Check: live.

### P-0111 Deleting a class that owns a table deletes its rows
- Statement: %SYSTEM.OBJ.Delete of a persistent class whose SqlTableName is a table removes the table's extent.
- Used by: INS-P8.10, INS-B8.1 (the edge rescue stages rows before the delete).
- Evidence so far: source comment at iris_vector_graph/schema.py:2958-2964 (measured against a 3.2.0 install).
- Check: live (3.2.0 fixture).

### P-0112 An unqualified SQL name resolves in the process's default schema
- Statement: a name given with no schema (here `DROP INDEX idx_props_key_val`) is looked up in the default schema
  (SQLUser unless configured), not in the IVG Schema.
- Used by: INS-P13, finding F-0107.
- Evidence so far: IRIS SQL documentation of default schema names; not checked here for DROP INDEX, whose resolution
  without ON TABLE may differ.
- Check: live (an index of that name in SQLUser and in the IVG Schema; run setup; see which goes).

### P-0113 Dynamic SQL checks the caller's privileges; globals check only the database resource
- Statement: a %SQL.Statement run inside a routine is checked against the calling user's SQL privileges, while a
  global read or write is checked only against the database resource.
- Used by: INS-P10.12, the read path rule (legacy.py:277-293) and every SqlPrivilege.RequireSelect call.
- Evidence so far: source comments in Graph/KG/SqlPrivilege.cls:1-10 and legacy.py:285-288;
  tests/e2e/test_460_r280_sql_global_readers_privilege_e2e.py (live, not opened in detail).
- Check: live (a role with EXECUTE and no SELECT).
