# Premises of module 08 (Cypher on the SQL path)

Each premise is cited from `ontology/08-cypher-sql.md` as `assumed:P-08kk`. None is checked by this uplift; each says
what would check it.

### P-0801 IRIS runs a functional index's callbacks inside the row's transaction
- Statement: an insert, update or delete of a row in `Graph_KG.rdf_edges` or `rdf_labels` runs the declared
  functional index's `InsertIndex` / `UpdateIndex` / `DeleteIndex` (`Graph.KG.AdjIndex`, `Graph.KG.LabelIndex`) in the
  same process and transaction, and a rollback undoes the globals they set.
- Used by: CYP-B6.12 (a Cypher write keeps `^KG` current with no call of its own), CYP-P1.
- Evidence in the product: `iris_src/src/Graph/KG/AdjIndex.cls:1-26`, ADR-0008; live regression
  `tests/e2e/test_252_cypher_read_after_write_e2e.py::test_raw_sql_insert_commit_and_rollback` (not run here).
- Check: live (a Cypher CREATE inside a caller transaction, then ROLLBACK, then read `^KG("out")`).

### P-0802 A transaction level opened by a SQL function nests under the caller's transaction
- Statement: `Graph_KG.Txn_Begin(1)` (ObjectScript `TSTART` run as a SQL function on the writing cursor) opens a level
  under a transaction the caller opened with SQL `START TRANSACTION` or the driver's autocommit off, and
  `Txn_End` / `Txn_Undo` (`TCOMMIT` / `TROLLBACK 1`) end only that level.
- Used by: CYP-B6.2, CYP-I6.3, CYP-P2.
- Evidence in the product: `iris_vector_graph/_write_txn.py:1-30` (measured on IRIS 2026.3, driver 5.4.0, per its
  docstring); `tests/e2e/test_464_caller_txn_e2e.py` (not run here).
- Check: live on IRIS Community 2026.1 with both drivers.

### P-0803 A failed SQL statement takes back only itself
- Statement: when one SQL statement fails inside an open transaction, IRIS undoes that statement's own changes and
  leaves the transaction open with its earlier work.
- Used by: CYP-I6.3, CYP-T1.5 (a failed read does not roll back the caller), CYP-P3.
- Evidence in the product: comment at `iris_vector_graph/stores/iris_sql_store.py:1552-1553`.
- Check: live (two statements in one transaction, the second violating a unique key; count rows before commit).

### P-0804 A duplicate unique key is refused with SQLCODE -119 and writes nothing
- Statement: an `INSERT` that would duplicate `rdf_edges`' unique key `(s, p, o_id, graph_id, ekey)` fails with
  SQLCODE -119 and adds no row.
- Used by: CYP-B6.7.7 and finding F-0805 (the literal-endpoint edge CREATE), CYP-P4.
- Evidence in the product: `iris_vector_graph/_write_txn.py:46-49`; the comment in
  `tests/e2e/test_234_multigraph_cypher_e2e.py::test_mode_off_never_makes_a_second_edge`.
- Check: live.

### P-0805 Doubling a single quote is a complete escape for an IRIS SQL string literal
- Statement: inside `'...'` in IRIS SQL, `''` stands for one `'` and no other character (backslash, NUL, a newline)
  ends or changes the literal.
- Used by: CYP-T5.1 (the graph name is inlined as `'<name with '' doubled>'`), the captured ids an all-graphs write
  inlines (CYP-T6.13.1), CYP-P5.
- Evidence in the product: `iris_vector_graph/cypher/translator.py:2085-2086`;
  `tests/unit/test_460_all_graphs_writes.py::test_a_graph_name_is_quoted_as_a_literal` (unit, text only).
- Check: live, with graph names holding `'`, `\`, `$Char(0)` and a newline; GraphKey.Validate refuses control
  characters, which narrows it.

### P-0806 The driver runs one SQL statement per execute call
- Statement: `cursor.execute(sql, params)` on intersystems-irispython runs one statement; text after a `;` or a `--`
  cannot add a second statement.
- Used by: the impact of F-0815 and F-0814 (pasted text can change one statement, not add another), CYP-P6.
- Evidence in the product: `iris_vector_graph/stores/iris_sql_store.py:1522-1531` (one execute per statement).
- Check: live, under both driver versions 5.4.0 and 5.4.1.
