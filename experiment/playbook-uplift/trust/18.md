# Premises: 18 Snapshots

None of these is checked in this uplift; each names the check that would.

### P-1801 SELECT * returns columns in declaration order
- Statement: IRIS returns `SELECT *` columns in the table's column order, which for DDL-created tables is the order
  of the `CREATE TABLE` (later `ALTER TABLE ADD` columns at the end).
- Used by: the archive's column order and the merge restore's first-column guard (`snapshot.py:866-874`,
  `:1287-1292`); finding F-1802 depends on it.
- Check: `SELECT TOP 1 * FROM Graph_KG.rdf_edges` and read `cursor.description`.

### P-1802 The Native API round-trips every non-vector global value through str()
- Statement: `iris_obj.get` returns each value (including `$List` ledger records) in a form whose `str()` the
  restore can `set` back to an equal value; only the number-or-string type is lost.
- Used by: `_export_global_to_ndjson` / `_import_global_from_ndjson` for `^KG`, `^NKG`, `^BM25Idx`, `^IVG.Ledger`
  and the ledger storage globals.
- Check: upstream `tests/integration/test_ledger_snapshot.py` compares ledger records after a round trip (live); a
  byte-level comparison of every node before and after would check the rest.

### P-1803 A snapshot archive is untrusted input
- Statement: whoever can place a file where `restore_snapshot` reads it controls its content; the operator chooses
  the file but cannot be assumed to have inspected it.
- Used by: the column-name check, the vector-text check and the restore allow-list (`snapshot.py:368-378`,
  `:412-422`); CHANGELOG 4.6.0 says to "treat a snapshot archive from elsewhere as untrusted input".
- Check: none needed; it is a stance. What the guards do not cover (any content written into allowed globals) is
  out of scope.
