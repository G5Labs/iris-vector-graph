# Premises of module 03 (direct writes)

Cited from `ontology/03-writes.md` as `assumed:P-03kk`. None is checked in this uplift. Several were measured by the
product team on IRIS 2026.3 with driver 5.4.0 (the source comments say so); that is their evidence, not ours.

### P-0301 ObjectScript transaction levels nest, and SQL COMMIT and ROLLBACK end every level
- Statement: `TSTART` inside a transaction raises `$TLEVEL`; `TCOMMIT` at an inner level only lowers it; `TROLLBACK 1`
  takes back that level's SQL rows and globals alone. SQL `START TRANSACTION` inside a transaction does nothing, and
  SQL `COMMIT` / `ROLLBACK` end every level.
- Used by: WRT-T2.4, WRT-B2.2, WRT-B2.3, WRT-I2.11 (the whole write-level design).
- Source: iris_src/src/Graph/KG/Txn.cls:1-11; iris_vector_graph/_write_txn.py:15-21.
- Check: live, tests/e2e/test_464_caller_txn_e2e.py (not run here).

### P-0302 The DB-API `executemany` skips a refused row of several without raising
- Statement: with intersystems-irispython 5.4.0 on IRIS 2026.3, `executemany` raises IRIS's refusal for a one-row
  batch, but for a batch of several it skips the refused row (SQLCODE -104 too wide, -108 NULL in NOT NULL) and
  `rowcount` is the number written.
- Used by: WRT-T8, WRT-T8.1, WRT-T8.2 (the read-back backstop).
- Source: iris_vector_graph/_batch_check.py:1-15.
- Check: live, a 3-row `executemany` into `rdf_labels` with one 129-character label.

### P-0303 IRIS's filer writes no value whose text equals the stored text
- Statement: `UPDATE ... SET val = 30` over the stored string `'30'` answers one row and leaves the string, for a bound
  integer, a UDF's number, `UPDATE %NOCHECK` and `%OpenId` / `%Save` alike.
- Used by: WRT-P5.12 and the reason `Graph.KG.PropWrite` exists (WRT-B5.7).
- Source: iris_src/src/Graph/KG/PropWrite.cls:1-8; CHANGELOG.md:108-117.
- Check: live, the same UPDATE without `Prop_Set` and a `$ListBuild` read of the data node.

### P-0304 `%NOINDEX` rows are invisible to indexed reads, and `%NOCHECK` skips the table's checks
- Statement: an `INSERT %NOINDEX` writes the row and no index entry, so `WHERE node_id = 'x'` through an index finds
  nothing until `%BuildIndices`; `%NOCHECK` skips unique, foreign-key and NOT NULL checks.
- Used by: WRT-T7.9, WRT-B7.10 and the bulk loader's dedupe scans.
- Source: iris_vector_graph/bulk_loader.py:182-199; iris_vector_graph/bulk_loader.py:403-410.
- Check: live, tests/integration/test_bulk_loader_live.py (not run here).

### P-0305 A SQL function runs in the calling connection's own server process
- Statement: `SELECT Graph_KG.Txn_Begin(?)` on a cursor runs in that connection's IRIS process, so its `TSTART` nests
  in the caller's transaction on that connection; a Native API object made from another connection does not.
- Used by: WRT-T2.4, WRT-T2.13, finding F-0305.
- Source: iris_vector_graph/_write_txn.py:15-21; iris_src/src/Graph/KG/Txn.cls:3-5.
- Check: live, `SELECT $JOB` from a cursor and from the engine's `_iris_obj()` on a `from_connect` engine.

### P-0306 A rollback does not undo `$Increment`
- Statement: counters set with `$Increment` inside a transaction keep their new value after `TROLLBACK`.
- Used by: WRT-B2.12.
- Source: docs/USER_GUIDE.md:252-258.
- Check: live, `TSTART  Set x=$Increment(^X)  TROLLBACK  Write ^X`.

### P-0307 IRIS words a too-wide column value as a failed field validation
- Statement: SQLCODE -104 on an INSERT carries the text "Field validation failed" (and "failed validation" in
  `%msg`), which `create_node`'s duplicate test matches with the words "validation failed".
- Used by: finding F-0306.
- Source: iris_vector_graph/_engine/nodes_edges.py:1097-1102.
- Check: live, `create_node("x", graph="g" * 300)` and read the exception text before the except clause.
