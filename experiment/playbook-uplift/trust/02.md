# Premises of module 02 (graph identity)

Cited from `ontology/02-graph-identity.md` as `assumed:P-02kk`. None is checked in this uplift; each says what would
check it.

### P-0201 IRIS takes the subscript text "0" and the number 0 as one subscript
- Statement: IRIS canonicalizes a subscript that is a canonical number, so `^KG("out", "0", ...)` and
  `^KG("out", 0, ...)` are the same node. `"00"` and `"0.0"` are not canonical and stay distinct strings.
- Used by: GID-P2.10, GID-X3.1, GID-I2.5 (the reason the name "0" is reserved).
- Source: docs/adr/0003-two-graph-key-derivations.md:92-98.
- Check: live, `Set ^X("0")=1 Write $Data(^X(0))` answers 1; `$Data(^X("00"))` answers 0.

### P-0202 `$ZStrip(x, "*C")` strips C1 control characters too
- Statement: the ObjectScript mask `C` covers code points 0-31 and 127-159, so `GraphKey.Validate` refuses a name
  holding, for example, `$Char(133)`. The Python mirror refuses only code points below 32 and 127.
- Used by: GID-B3.8 and finding F-0203. If the mask is 0-31 and 127 only, F-0203 is closed by this premise failing.
- Source: InterSystems ObjectScript reference for `$ZSTRIP` (mask codes); iris_src/src/Graph/KG/GraphKey.cls:44.
- Check: live, `Write ##class(Graph.KG.GraphKey).Validate("a"_$Char(133))` on IRIS Community 2026.1.

### P-0203 IRIS SQL returns `$Char(0)` for an empty-string VARCHAR
- Statement: an empty string stored in a VARCHAR column comes back to ObjectScript as `$Char(0)`, so a graph name read
  from `graph_id` can carry NUL padding that is not part of the name.
- Used by: GID-T3.3 (NUL is stripped, not refused).
- Source: iris_src/src/Graph/KG/GraphKey.cls:34-37; tests/integration/test_graph_key_behaviour.py:55-58.
- Check: live, the integration test `test_for_index_strips_control_padding` and a `SELECT graph_id` probe.

### P-0204 The empty string cannot be a global subscript
- Statement: `^KG("out", "", ...)` raises `<SUBSCRIPT>`, so the default graph needs a non-empty key in every global.
- Used by: GID-P2.11, GID-B2.2 (index key 0), GID-B2.3 (ledger key `$Char(1)`).
- Source: docs/adr/0001-graph-key-as-first-subscript.md:23-24; docs/USER_GUIDE.md:441-445.
- Check: live, `Set ^X("")=1` raises `<SUBSCRIPT>`.

### P-0205 `$Order` hands back a canonical-number subscript as a number
- Statement: a graph named like a canonical number (`"5"`, `"-1"`) is stored as a numeric subscript; the Native API's
  `nextSubscript` returns it as an int, and `str()` of it is the original name. So the Python listing that turns
  `^KG("out", key)` back into a name (`"" if str(key) == "0" else str(key)`) gives back every valid name.
- Used by: GID-T2.9.
- Source: iris_vector_graph/stores/lazy_kg.py:66-80.
- Check: live, create an edge in graph `"5"` and in graph `"-1"`, then compare `list_graphs()` with the
  `graphs_with_edges` listing.
