# Premises of module 04 (ADJ, adjacency)

Premises about IRIS that the adjacency index, the degree cache and the graph-version token rely on. None is checked
by this builder; each says what would check it. The system premises P-0001 (rollback of a stopped process), P-0002
(dirty reads), P-0003 (an unlock inside a transaction is deferred) and P-0004 (locks freed on exit) are in
`TRUST.md` and are cited from `04-adjacency.md` too.

### P-0401 A rollback does not undo $Increment
- Statement: `$Increment` of a global inside TSTART is not taken back by TROLLBACK; the counter keeps the stepped value.
- Used by: the source generation (`^KG("gen")`), the graph-version token (`^KG("__version")`), the no-lock mark
  (`^IVG.AdjNoLock`); ADR-0010 and ADR-0012 are built on it ("a rolled-back write over-bumps").
- Evidence the product has: `tests/integration/test_236_token_write_paths.py::test_25_a_rolled_back_bump_is_not_undone`
  asserts it on live IRIS (not run here).
- Check: live (bump inside TSTART, TROLLBACK, read the counter from a second process).

### P-0402 A process's own lock never blocks its own lock request
- Statement: a process that holds `^IVG.AdjW(g)` in shared mode is granted its own exclusive request on the same name
  at once, when no other process holds it.
- Used by: `Graph.KG.Adj.Degree` (a reader inside the writer's own transaction gets its probe, stores, and the
  rollback takes the store back, Adj.cls:40-44).
- Evidence the product has: `tests/e2e/test_degree_cache_live.py::test_a_reader_inside_the_writers_own_transaction_is_rolled_back_with_it`.
- Check: live (one process: shared lock, then exclusive :0 on the same name).

### P-0403 Shared locks do not conflict with each other
- Statement: any number of processes may hold `Lock +name#"S"` at once; a shared request waits only for an exclusive
  holder.
- Used by: the writer lock rule (ADR-0012: "writers never wait for writers"), the rebuild's shared parent lock running
  beside row writers.
- Check: live (two processes take the shared lock; neither waits).

### P-0404 A lock on a parent name conflicts with another process's lock on a child name
- Statement: a shared lock held on `^IVG.AdjW` makes another process's exclusive request on `^IVG.AdjW(g)` fail, and
  an exclusive lock held on `^IVG.AdjW(g)` makes another process's shared request on `^IVG.AdjW` wait.
- Used by: `Adjacency.RemoveAll` and `BeginRebuild` (one lock covers every graph), and so the claim that no reader
  caches a count from a half-built index.
- Check: live (process A: `Lock +^IVG.AdjW#"S"`; process B: `Lock +^IVG.AdjW(0)#"E":0` must fail).

### P-0405 IRIS SQL filing ignores a functional index callback's status
- Statement: an error `%Status` returned (or thrown) by `InsertIndex`/`UpdateIndex`/`DeleteIndex` of a
  `%Library.FunctionalIndex` does not fail the row's INSERT, UPDATE or DELETE.
- Used by: `Adjacency.WriterLock` (4.7.0 row 17: a refused lock left the row written and `^KG` without the edge, so the
  writer now writes without the lock).
- Evidence the product has: `CHANGELOG.md` 4.7.0 (lines 174-178) and
  `tests/e2e/test_470_silent_writers_e2e.py::test_a_write_while_the_writer_lock_is_held_still_writes_kg`.
- Check: live (a callback that returns an error; the row is still there).

### P-0406 A write to a read-only database raises PROTECT
- Statement: a global Set by a login that holds the database at R raises `<PROTECT>`.
- Used by: `Graph.KG.Adj.Degree` (skips the cache store on `<PROTECT>` and returns the count; any other error is raised).
- Check: live (a login with R only calls `Graph.KG.Adj.Degree` on a node with no current entry).

### P-0407 A functional index callback runs inside the row's transaction
- Statement: IRIS calls `Graph.KG.AdjIndex` callbacks in the same transaction as the row write, so the callback's global
  writes commit and roll back with the row; `%BuildIndices` calls `PurgeIndex` once and then `InsertIndex` for every row
  (in several jobs when asked).
- Used by: spec 252 FR-001 ("a rollback undoes both"), the claim that a declared index cannot drift from its rows,
  `TraversalBuild.BuildKG`'s indexed path.
- Evidence the product has: `tests/e2e/test_252_writer_paths_e2e.py::test_a_failed_ledger_commit_leaves_no_adjacency`.
- Check: live (insert a row in TSTART, roll back, `^KG("out")` has no entry).

### P-0408 A rollback restores only what its own transaction changed
- Statement: TROLLBACK restores the old values of the nodes its own transaction set or killed; a node another process
  set afterwards, which the transaction never touched, survives the rollback.
- Used by: the analysis in F-0401 (a reader's cache entry stored between a writer's Kill and its rollback stays).
- Check: live (process A kills a subtree in TSTART; process B sets a new node under it; A rolls back; B's node is there).

### P-0409 A TROLLBACK with no argument rolls back every level
- Statement: `TROLLBACK` without an argument ends all transaction levels of the process, including levels its caller
  opened; `TROLLBACK 1` ends one.
- Used by: the analysis in F-0409 (`TraversalBuild.BuildKG` failure path) and CHANGELOG 4.6.4's caller-transaction rule.
- Check: documentation (IRIS TROLLBACK reference) or live (TSTART twice, TROLLBACK, `$TLevel` = 0).
