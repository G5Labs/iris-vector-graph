# Trust: module 17 (operations and runtime)

Premises the OPS statements rest on. None was checked in this uplift unless the entry says so; "Check" names what
would check it. Statements cite them as `assumed:P-17kk`.

### P-1701 IVG runs on IRIS 2025.1 or later, and is exercised on Community 2026.1
- Statement: IRIS 2025.1 Community is the documented minimum (HNSW needs 2025.1; ACORN-1 and `CROSS JOIN LATERAL`
  need 2026.1). The repository's CI runs `docker-compose.yml`'s `iris-community:2026.1` on every push; the integration
  and E2E suites were run upstream on `irishealth:2026.3.0AI.113.0`.
- Source: `docs/ADMIN_GUIDE.md` section 1 ("checked 2026-10-24"), `docker-compose.yml:30`.
- Used by: OPS-P1 and every claim that a behaviour holds "on IRIS".
- Check: this uplift's orchestrator runs on IRIS Community 2026.1 (`$IVG_TEST_CONTAINER`); 2025.1 and the AI builds
  are not run here.

### P-1702 IRIS Community limits cores and ignores a licence key
- Statement: Community Edition refuses to start ("Too many Cores") on a host with more cores than its licence allows,
  and ignores a mounted `iris.key`.
- Source: `docker-compose.yml:17-22`, `docs/ADMIN_GUIDE.md` section 1.
- Used by: OPS-P2, the deploy recipes.
- Check: documentation only (vendor licence terms).

### P-1703 Only IRIS AI builds ship the %AI package
- Statement: `%AI.MCP.Service`, `%AI.Tool`, `%AI.ToolSet` and `%AI.Policy.ConsoleAudit` exist on IRIS AI builds
  (AI Hub) and not on Community 2026.1.
- Source: `docs/ADMIN_GUIDE.md` section 4 ("The MCP classes").
- Used by: OPS-P3. The class-deploy consequence (setup skips Graph.KG.MCPService, MCPToolSet and MCPTools when the
  server lacks `%AI`) is stated by module INS (01), which owns class deploy.
- Check: the orchestrator's preflight log on Community 2026.1 shows `ERROR #5373: Class '%AI.MCP.Service' ... does not
  exist` when the classes are compiled unconditionally (output seen in this uplift's preflight, not a run of this
  module).

### P-1704 The IRIS Python driver provides the client connection and the Native API
- Statement: `intersystems-irispython` (pulled in by `intersystems-iris`) provides `iris.connect` / `iris.dbapi`
  (DB-API cursors over the SuperServer) and `iris.createIRIS(conn)` with `classMethodValue`, `get`, `set`, `kill`,
  `isDefined` and `nextSubscript`. Each connection is served by one IRIS server process.
- Source: `pyproject.toml:41-48`, `uv.lock` (intersystems-iris 5.3.3, intersystems-irispython 5.3.2).
- Used by: OPS-P4, the client host, the HTTP server's IRIS link, the command line's direct commands.
- Check: implicit in every live run of this uplift (the driver is how the tests connect).

### P-1705 Inside IRIS, embedded Python exposes iris.sql, iris.cls and iris.gref
- Statement: a process running `irispython` or a `[ Language = python ]` method can import an `iris` module whose
  `sql.prepare/exec`, `cls(name)` and `gref(name)` reach the current namespace in the current process. Outside IRIS the
  `iris-embedded-python-wrapper` answers unknown names with MagicMocks.
- Source: `iris_vector_graph/embedded.py:1-44`, `iris_vector_graph/embedded.py:136-150`.
- Used by: OPS-P5, the in-IRIS connection and host.
- Check: upstream `tests/e2e/test_embedded_irispython_e2e.py` (live, not run in this uplift).

### P-1706 Another package can overwrite iris/__init__.py
- Statement: `intersystems-irispython`, `iris-embedded-python-wrapper` and `sqlalchemy-iris` each install
  `iris/__init__.py`; the last one installed wins, and sqlalchemy-iris 0.18.1's copy loads a driver file name that
  driver 5.4.0 does not ship, leaving `iris.createIRIS` a mock.
- Source: `iris_vector_graph/_iris_compat.py:1-18`.
- Used by: OPS-P6, OPS-B4.7.
- Check: upstream `tests/unit/test_iris_dbapi_import.py` (unit, not run here).

### P-1707 IRIS refuses a string over 3,641,144 characters
- Statement: a class method whose reply is longer than IRIS's maximum string raises `<MAXSTRING>`; a `%DynamicArray`
  `%ToJSON` past it dies with `<STRINGSTACK>` on the server, which the client sees only as `<THROW>`.
- Source: `iris_vector_graph/host.py:52-77`.
- Used by: OPS-P7, OPS-B4.4.
- Check: documentation and the upstream measurement on IRIS 2026.3 AI build 113 (host.py comment).

### P-1708 IRIS refuses a statement with about 1,000 bound parameters
- Statement: preparing a statement near 1,000 `?` markers fails (SQLCODE -1 at `:%qpar(1000`); the IN lists failed at
  2,000.
- Source: `iris_vector_graph/stores/iris_sql_store.py:1112-1114`, `iris_vector_graph/stores/iris_sql_store.py:1303-1305`.
- Used by: OPS-P8, the 500-id chunking of the SQL adapter.
- Check: none in this uplift.

### P-1709 Embedded iris.sql binds an empty string as SQL NULL
- Statement: under embedded Python a bound `''` reaches the SQL engine as NULL, so a NOT NULL column holding `''`
  (graph_id of the default graph) refuses it; `stmt.execute(*params)` with hundreds of values overflows the call stack.
- Source: `iris_vector_graph/embedded.py:188-190`, `iris_vector_graph/embedded.py:328-336`.
- Used by: OPS-P9, OPS-T4.6.3.
- Check: upstream `tests/e2e/test_embedded_wgproto_e2e.py` (live, not run here).

### P-1710 VECTOR_L2 is a distance
- Statement: IRIS's `VECTOR_L2(a, b)` returns the Euclidean distance between the vectors, so a smaller value is a
  closer vector; `VECTOR_COSINE` and `VECTOR_DOT_PRODUCT` are similarities (larger is closer).
- Source: InterSystems IRIS SQL reference for the vector functions (vendor documentation).
- Used by: OPS-P10 and finding F-1705.
- Check: a live query of `VECTOR_L2` over two known vectors.

### P-1711 INFORMATION_SCHEMA.ROUTINES lists only routines the caller may run
- Statement: a user without EXECUTE does not see a routine in `INFORMATION_SCHEMA.ROUTINES`; `SELECT TOP 0
  <schema>.<name>(NULL)` is refused at Prepare with SQLCODE -359 when the routine does not exist, -99 when the caller
  may not run it, and -357 when it is a procedure.
- Source: `iris_vector_graph/_engine/admin.py:705-714`.
- Used by: OPS-P11, OPS-T2.8.1.
- Check: none in this uplift.

### P-1712 A Python warning is not an exception unless the filter says so
- Statement: `warnings.warn(UserWarning(...))` prints (once per location, by default) and returns; it raises only when
  the process's warning filter is set to `error` for that category.
- Source: Python standard library documentation (`warnings`).
- Used by: OPS-P12 and finding F-1703.
- Check: standard library behaviour; not version-dependent for 3.10 to 3.13.

### P-1713 A %-method run through the wgproto Callin worker can crash it
- Statement: in the Callin worker behind IRIS's MCP service, calling a `%` system method through `iris.cls` segfaults
  the worker (signal 11), where it used to raise `AttributeError`.
- Source: `iris_vector_graph/host.py:3-18`, `iris_vector_graph/embedded.py:468-474` (measured upstream on Build 154).
- Used by: OPS-P13, OPS-X4.2.
- Check: none in this uplift.

### P-1714 Core Python dependencies
- Statement: the core install needs `intersystems-iris>=1.0.0`, `iris-embedded-python-wrapper>=0.5.20`,
  `pydantic>=2.0.0`, `numpy>=1.24.0`, `requests>=2.28.0` and `tzdata>=2025.2` on Python 3.10 or later; `uv.lock` pins
  pydantic 2.13.4, numpy 2.3.5 (2.2.6 on 3.10), requests 2.34.2, tzdata 2026.2, wrapper 0.5.20. The command line needs the
  `cli` extra (click, httpx), the HTTP server the `full` extra (fastapi, uvicorn). RDF, communities and PLAID extras add
  rdflib below 8, pyshacl, igraph, leidenalg, networkx and scikit-learn.
- Source: `pyproject.toml:38-106`, `uv.lock`.
- Used by: OPS-P14.
- Check: the uplift venv (`$RUN_DIR/venv`) reports the locked versions listed above (read with importlib.metadata, not
  a test).

### P-1715 A LIST ERROR after another connection's %BuildIndices is tied to the statement text
- Statement: a connection that ran a statement before another connection ran `%BuildIndices` on its class gets
  `<LIST ERROR> ... type detected : 0` where that statement should fail with its SQLCODE (-119, -121); a statement text
  the connection has not run before reports correctly.
- Source: `iris_vector_graph/utils.py:118-130`.
- Used by: OPS-P15, OPS-T9.6.
- Check: none in this uplift.

- Source: `docker/enterprise/docker-compose.yml:1-9`, `deploy/iris-build/Dockerfile:14-16`.
- Used by: OPS-P16, OPS-B11.3.
- Check: documentation only.
