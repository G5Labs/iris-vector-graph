# Premises of module 15 (INT: FHIR graphs, code maps, table maps, RDF, SHACL, PROV)

Each premise is a claim about IRIS, the InterSystems FHIR server or a Python library that module 15 relies on and that
this uplift did not check. "Check" says what would.

### P-1501 Only IRIS for Health has the FHIR server; the FHIR graph class compiles everywhere
- Statement: `HS.FHIRServer.*` (classes and the `HS_FHIRServer` SQL schema) exist only in a FHIR-enabled namespace of
  IRIS for Health (the `ivg-iris-enterprise` image in the repo's tests). `Graph.KG.FHIRGraph` reaches them only by
  dynamic SQL and `$ClassMethod`, so it compiles on IRIS Community, and `Register` answers "no FHIR repository".
- Used by: INT-F12.1, INT-F3.2; every FHIR E2E test cited by module 15 needs the enterprise image.
- Source: `iris_src/src/Graph/KG/FHIRGraph.cls:8-11`, spec 235 clarification of 2026-09-27.
- Check: compile the class on IRIS Community and call `Register()`; expect the error, not a compile failure.

### P-1502 The repository's change feed is Rsrc plus RsrcVer with rising row ids
- Statement: a first create writes only `Rsrc` (new `Rsrc.ID`); every later write, a delete included, archives the
  prior version into `RsrcVer` under a new, larger `RsrcVer.ID` and updates `Rsrc` in place. IDs never go back.
- Used by: INT-F5.1, INT-F12.3, the watermarks (INT-D7), and the "repository behind the watermarks" rule (INT-F5.5).
- Source: `iris_src/src/Graph/KG/FHIRGraph.cls:13-18`; `docs/FHIR_GRAPH.md` "Sync". ISC internals, not documented by ISC
  as a contract.
- Check: on IRIS for Health, PUT, PUT again and DELETE one resource and read both tables' IDs.

### P-1503 FHIR deletes are soft
- Statement: a deleted resource keeps its `Rsrc` row with `Deleted = 1`; the search-index rows of a deleted resource
  are removed.
- Used by: INT-F12.4, liveness (`Liveness`), rebuild's stale pass, `ResolveConcepts` (it also checks `Rsrc`).
- Source: `iris_src/src/Graph/KG/FHIRGraph.cls:469-470`, `:853-855`.
- Check: delete a resource and read `Rsrc.Deleted` and its search tables.

### P-1504 The server schema lists the R4 patient compartment params
- Statement: `HS.FHIRServer.Schema.GetCompartmentParamsForType` returns, per resource type, the base R4 Patient
  CompartmentDefinition params (145 entries, 66 with params in the vendored R4 package).
- Used by: INT-F2, INT-F2.1, INT-F2.9.
- Source: spec 235 Assumptions; the E2E oracle `tests/e2e/test_235_compartment_e2e.py::test_membership_matches_server`
  compares against the server's `<Type>Compartments` tables (not run here).
- Check: run that E2E test on the enterprise image.

### P-1505 Task Manager counts in whole minutes
- Statement: `%SYS.Task` with `DailyFrequency = 1` repeats every `DailyIncrement` minutes; it cannot run more often than
  once a minute.
- Used by: INT-F9.1, INT-F9.5, the 60-second floor of INT-F3.5.
- Source: `iris_src/src/Graph/KG/FHIRGraph.cls:664-713`.
- Check: IRIS documentation for `%SYS.Task`.

### P-1506 Dynamic SQL in server code runs with the caller's SQL privileges
- Statement: `%SQL.Statement` prepared and run inside `Graph.KG.FHIRGraph` checks the SQL privileges of the user the
  calling process runs as, so a caller who may not read the repository's tables cannot read their codes through it.
- Used by: INT-F12.2; `docs/FHIR_GRAPH.md` "Security model" says codes are read "under the caller's own SQL privileges".
- Source: `docs/FHIR_GRAPH.md:551-559`.
- Check: call `ResolveConcepts` as a user without SELECT on `HSFHIR_X0001_S` and expect a privilege error.

### P-1507 rdflib 6 and 7 have ConjunctiveGraph; rdflib 8 removes it
- Statement: `from rdflib import ConjunctiveGraph` works on rdflib 6.x and 7.x (deprecated in 7) and fails on rdflib 8.
- Used by: INT-R1.19, INT-R1.20, the "rdflib 8" cells; the `[rdf]` and `[full]` extras pin `rdflib>=6.0.0,<8`.
- Source: `docs/KNOWN_ISSUES.md:716-722`, `pyproject.toml:79-92`, `pyproject.toml:274-276`.
- Check: import it under each major version.

### P-1508 pySHACL checks every named graph of a ConjunctiveGraph data graph
- Statement: `pyshacl.validate(ConjunctiveGraph, ...)` checks the triples of every context of the data graph, so a
  focus node in a named graph is checked.
- Used by: INT-S1.12, INT-S1 ("validates the labels, properties and edges of every graph").
- Source: `docs/SEMANTIC_LAYER.md:158-160`; `iris_vector_graph/_engine/shacl.py:233-240`.
- Check: validate a ConjunctiveGraph whose only violating node sits in a named context.

### P-1509 The default SQL schema for an unqualified table name is SQLUser
- Statement: in IRIS, `CREATE TABLE Patients` makes `SQLUser.Patients`, and `INFORMATION_SCHEMA.COLUMNS.TABLE_SCHEMA`
  for it is `SQLUser`, not `USER`.
- Used by: INT-M1.4 and finding F-1504.
- Source: IRIS SQL documentation (default schema); `iris_vector_graph/_engine/fhir.py:113-120`.
- Check: create an unqualified table and read its row in `INFORMATION_SCHEMA.COLUMNS`.

### P-1510 One IRIS string holds about 3.6 million characters
- Statement: an ObjectScript string, and so one class method answer, cannot exceed the IRIS long-string limit
  (3,641,144 characters); building a longer one raises `<MAXSTRING>`.
- Used by: INT-V1.6 (PROV window), INT-C2.5 (why grouping runs in IRIS), the JSON answers of `LinkReport` and
  `ResolveConcepts`.
- Source: `docs/SEMANTIC_LAYER.md:267-269`; spec 235 research R17.
- Check: IRIS documentation; a `QueryWindow` over a large temporal history.

### P-1511 The FHIR search index keeps 220 characters of a canonical
- Statement: the repository's search columns hold a canonical URL and version cut to 220 characters (`MAXLEN = 220`,
  `TRUNCATE = 1`), split on the first `|`.
- Used by: INT-F1.12 (`CANONICALMAX`).
- Source: `iris_src/src/Graph/KG/FHIRGraph.cls:2720-2724`.
- Check: index a canonical longer than 220 characters and read its search row.
