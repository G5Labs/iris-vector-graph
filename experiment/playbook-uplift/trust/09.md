# Trust: module 09 (native Cypher executor)

Premises the NAT statements rely on. None is checked by this uplift; each says what would check it. The system
premise P-0002 (other processes read uncommitted writes) is also used, by NAT-T4.6 and NAT-B4.1.

### P-0901 $ZCRC mode 7 is a 32-bit CRC, so different inputs can share a value
- Statement: `$ZCRC(string, 7)` returns a CRC-32 of the string: about 4.3 billion values, so two different strings
  collide with probability about 2^-32, and among N strings some pair collides with probability about N^2 / 2^33.
- Used by: NAT-I3 and NAT-T5.4 (`Graph.KG.Cypher.Gen.For` names a compiled plan `IVGC.P<$ZCRC(shape, 7)>`),
  NAT-B1.11 (`Graph.KG.Cypher.Exec.Neighbours` tells relationships apart by `$ZCRC($LB(src, p, dst, ekey), 7)`).
- Check: IRIS documentation of `$ZCRC` modes; a live probe that finds two `$ListBuild` values with one CRC.

### P-0902 The adjacency index changes in the same transaction as the edge and label rows
- Statement: where `idx_edges_adj` and `idx_labels_adj` are declared as functional indexes (spec 252), every insert,
  update or delete of an `rdf_edges` or `rdf_labels` row writes `^KG("out"/"in")` or `^KG("label")` inside the
  statement's transaction, so a committed row and its index entry agree, and a rollback removes both.
- Used by: NAT-P2, NAT-T4.1 (the native path reads labels and neighbours only from `^KG`).
- Check: owned by the adjacency module (ADR-0008, ADR-0011); its drift tests. Not checked here.

### P-0903 A class that fails to compile can leave its process unable to prepare new SQL
- Statement: on IRIS 2026.3, after `$System.OBJ.Compile` of a class fails in a process, every later `%Prepare` of a
  statement text that process has not run before fails with `<UNDEFINED>lviter+16^%qaqpnl`.
- Used by: NAT-P3, NAT-B5.3 (in `sync` mode `Gen.Build` compiles in the reader's process).
- Check: the product's own observation, recorded in the docstring of
  `tests/e2e/test_257_compiled_plans_e2e.py::test_the_broken_builds_leave_the_session_process_able_to_compile_sql`
  (that test avoids the effect by failing builds on a separate connection; it does not assert the effect). A live
  probe: fail one compile in a process, then prepare a new statement there. Not run here; unknown on Community 2026.1.

### P-0904 A recompiled or deleted class takes effect at the next call in every process
- Statement: after a class is compiled or deleted, the next call to it from any process runs the new code or fails
  with a class-does-not-exist error; no process keeps calling an old copy across calls.
- Used by: NAT-T5.6 (each read computes the running stamp from `BuiltAt` of the classes as compiled now),
  NAT-T5.8 (called classes are not stamped), NAT-T5.26 (a run whose class is dropped fails over to SQL).
- Check: IRIS documentation on routine buffers and class compilation; a live probe recompiling `Graph.KG.Cypher.Exec`
  while another process repeats a native read.

### P-0905 Work-queue workers are other processes of the same namespace and user
- Statement: `$System.WorkMgr.%New()` queues run in separate IRIS processes in the caller's namespace, with the
  caller's roles, reading the same globals; their `^IRIS.Temp` writes are visible to the coordinator after
  `WaitForComplete`.
- Used by: NAT-P1, NAT-T3.14, NAT-T3.15 (`Graph.KG.Cypher.Exec.Parallel` and `Part`).
- Check: IRIS documentation of `%SYSTEM.WorkMgr`; the upstream e2e tests that force the split
  (`tests/e2e/test_253_scan_groups_e2e.py`, not run here).

### P-0906 The rdf_props class's TimeChanged moves on every recompile, DDL included
- Statement: `%Dictionary.CompiledClass.TimeChanged` for the class behind `Graph_KG.rdf_props` changes whenever that
  class is compiled again, including by `CREATE INDEX` or `DROP INDEX` on the table, and only then.
- Used by: NAT-T5.5, NAT-T5.7 (the property reader's cache and every compiled plan's stamp key on it).
- Check: a live probe: read TimeChanged, drop and re-create an index on `rdf_props`, read it again.

### P-0907 SET $LIST past a list's end pads it with empty elements, and $LIST of an empty element raises
- Statement: `Set $List(g, 4) = x` on an undefined or shorter `g` creates or extends it with empty elements, and
  `$List(g, 2)` on such an empty element raises `<NULL VALUE>` (where `$ListGet` would answer "").
- Used by: NAT-I5 and finding F-0905 (an entry re-created by a build that finished after `DropAll`).
- Check: IRIS documentation of `$LIST`; a one-line terminal probe.
