# Premises: 10 Graph algorithms and traversal

### P-1001 The Arno readers read USER's data whatever namespace calls them
- Statement: each `kg_*_global` reader, and the library's `init`, moves the process to USER and reads USER's `^KG`,
  whatever namespace called it.
- Used by: `Graph.KG.ArnoAccel.NativeResult` and `ReadsUser` (refuse outside USER), the store's `_arno_route` (Owner
  outside USER), `Load` and `CallFn` (restore the caller's namespace).
- Check: measured on arno-callout 1.1.0 in spec 236 (`specs/236-arno-callout-adoption/research.md:165-173`); not
  rechecked here and not known for 1.2.1.

### P-1002 An atomic increment is never undone and never repeats a value
- Statement: `$Increment` on a global is atomic across processes, and a rollback does not lower the value it set.
- Used by: the graph-version token `^KG("__version")` and `^NKG("$meta","version")`; the result cache's
  "read token before compute" protocol.
- Check: documented (`docs/ADMIN_GUIDE.md:315`, `docs/USER_GUIDE.md:252-258`); not checked live here.

### P-1003 A library call takes at most 34,808 characters of text at the default `zfheap`
- Statement: at the default `zfheap`, `$ZF(-5)` accepts 34,791 adjacency characters beside 17 of other arguments;
  one more raises `<OUT OF $ZF HEAP SPACE>`, and 65,536 or more `<MAX $ZF STRING>`.
- Used by: `NKGAccelTraversal.BFSJson`'s size gate (`ZFMAXCHARS`).
- Check: measured in spec 236 (`specs/236-arno-callout-adoption/research.md:193-207`); depends on the instance's
  `zfheap` setting.

### P-1004 The native PageRank reader reads only the default graph's adjacency
- Statement: `kg_pagerank_global`, called with `"^KG"`, reads `^KG("out", 0, ...)` and nothing of a named graph.
- Used by: the native route of `kg_PAGERANK()` in a namespace where a named graph has edges (ALG-B14.7).
- Check: none; the sources disagree (F-1001). A live run with a named graph's edges and arno-callout 1.2.1 would
  decide it.

### P-1005 The networkx functions named as references compute what their documents say
- Statement: `pagerank`, `pagerank(personalization=...)`, `betweenness_centrality`, `harmonic_centrality`,
  `eigenvector_centrality`, `core_number` and `strongly_connected_components` answer as documented, for the version
  in `uv.lock`.
- Used by: the docstrings and tests that state IVG's answers as networkx's.
- Check: upstream documentation only.
