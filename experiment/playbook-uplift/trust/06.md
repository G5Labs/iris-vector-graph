# Trust: module 06 (vectors and vector search)

Premises the VEC statements rely on. None is checked by this uplift; each says what would check it.

### P-0601 IRIS refuses an INSERT whose vector width differs from the column's declared width
- Statement: a value written to a `VECTOR(type, n)` column with more or fewer than `n` elements is refused with
  `SQLCODE -104` (field validation failed), for too short and too long alike.
- Used by: VEC-P1, VEC-B3.5, VEC-B1.15 (a table with no registry row is still held to its column width),
  `_reconcile_reused_route_width`, `place_quarantined`.
- Source: `docs/adr/0005-vector-width-is-not-declared-in-to-vector.md` (measured 2026-09-19 on `ivg-iris-enterprise`).
- Check: documentation and the ADR measurement only; a live INSERT of a 3- and a 6-element vector into a
  `VECTOR(DOUBLE, 4)` column on IRIS Community would check it for that build.

### P-0602 TO_VECTOR without a length makes a width mismatch raise; with a length it pads or truncates
- Statement: `VECTOR_COSINE(col, TO_VECTOR(:q, DOUBLE))` raises `SQLCODE -257` when `:q` has another width than the
  column; `TO_VECTOR(:q, DOUBLE, n)` silently pads or truncates `:q` to `n` and scores the reshaped value.
- Used by: VEC-P2, VEC-T5.6, VEC-I5.7 (F-0612), the generated `kg_KNN_VEC` procedure.
- Source: ADR-0005 table; pinned by `tests/integration/test_to_vector_width_regression_e2e.py`
  (`test_wrong_width_raises_minus_257`, `test_a_long_query_is_truncated_to_a_perfect_match`), a live test this uplift
  did not run.
- Check: run that test file against IRIS Community.

### P-0603 IRIS LIKE has no escape character unless ESCAPE names one
- Statement: in IRIS SQL `x LIKE 'a\_b%'` treats `\` as an ordinary character; `_` and `%` stay wildcards unless the
  predicate says `ESCAPE '\'`.
- Used by: VEC-P3, VEC-B6.13 (F-0616: `_glob_to_sql_like` escapes with a backslash and no `ESCAPE` clause).
- Check: documentation only (InterSystems SQL reference for LIKE); a live `SELECT 1 WHERE 'a_b1' LIKE 'a\_b%'`
  would check it.

### P-0604 CREATE TABLE inside a transaction is undone by its rollback
- Statement: on IRIS 2026.3 a `CREATE TABLE` run inside an open transaction is taken back, with its class, when the
  transaction rolls back; it is not durable when it runs.
- Used by: VEC-P4, VEC-X2.8 (a new route is refused inside the caller's transaction), VEC-T2.7.
- Source: the 4.7.0 comment at `iris_vector_graph/_engine/embeddings.py:531-536` ("measured on IRIS 2026.3"). The
  docstring at `embeddings.py:600-604` still says DDL is durable the moment it runs; the two disagree.
- Check: a live probe that creates a table inside TSTART, rolls back and looks for the class.

### P-0605 An UPDATE ... WHERE model_key IS NULL serializes concurrent claimants
- Statement: when two processes run the claim UPDATE on the same adopted registry row, IRIS row-locks it, so the
  second re-evaluates `model_key IS NULL` after the first commits, matches nothing, and its re-read sees the winner.
- Used by: VEC-P5, VEC-I1.23 (FR-009).
- Check: `tests/integration/test_embedding_registry_e2e.py::test_concurrent_claim_of_adopted_row` (20 rounds of two
  threads, live IRIS) asserts the outcome; not run here.

### P-0606 Only one embed queue worker runs at a time
- Statement: the operator runs at most one worker per namespace: either the Python `process_embed_queue` or the IRIS
  task (`Graph.KG.EmbedQueueTask`), not both, and not two of either.
- Used by: VEC-P7.23, VEC-Q7.24 (HD-0604). `ClaimPendingBatch` and `ProcessBatch` are plain ordered scans with no
  claim state or lock (`iris_src/src/Graph/KG/EmbedQueue.cls:22-25`, `:112-134`, `:258-268`).
- Check: none possible in code; it is an operating rule. Nothing in the product enforces or documents it to users.

### P-0607 IRIS builds an HNSW index only on a table with a single integer row id
- Statement: IRIS refuses `CREATE INDEX ... AS HNSW` on a table whose row identity is composite or VARCHAR, which is
  why every vector table has `emb_rowid BIGINT IDENTITY PRIMARY KEY` and its natural key as a UNIQUE constraint.
- Used by: VEC-P6, VEC-B2.12, the routed table DDL (`iris_vector_graph/_engine/schema.py:243-263`).
- Source: spec 227 research R2/R3 as cited in code comments; `docs/migration/v4.0.0.md:97-128`.
- Check: a live `CREATE INDEX ... AS HNSW` on a VARCHAR-keyed table.

### P-0608 A foreign key with no ON DELETE action refuses deleting a referenced row
- Statement: deleting a `Graph_KG.nodes` row while a routed vector row references it through
  `fk_<table> (graph_id, node_id)` fails (`SQLCODE -124`) and deletes nothing.
- Used by: VEC-P7, VEC-T2.20, VEC-B3.15 (F-0618).
- Check: documentation; a live delete of a node that has a routed vector would check it.
