# Findings: 10 Graph algorithms and traversal

Module file: `ontology/10-algorithms.md`. Evidence is reading the code at pin `3eaa79cf`; nothing here was run.

### F-1001 A native reader answers default-graph calls in a namespace where a named graph has edges
- Statement: ALG-B14.7 (also ALG-I3, ALG-P4).
- Evidence: `arno_readers.route` returns `"native"` for `graph=""` without asking whether any other graph holds edges
  (`iris_vector_graph/arno_readers.py:257-280`). `_execute_pagerank` calls `_native_answer("pagerank", ...)` with no
  `_named_graph_with_edges()` probe (`iris_vector_graph/stores/iris_sql_store.py:2388-2400`), whereas the BFS route
  has exactly that guard (`_only_default_graph`, `iris_sql_store.py:1842-1858`) and so do the `^NKG` tiers
  (`iris_sql_store.py:3322`). The proof gate empties USER with `EraseAll` and loads default-graph fixtures only
  (`scripts/arno_reader_gate.py:73-82`), so `pagerank`'s proof (`docs/dev/arno-reader-proof.json`) covers no namespace
  with named-graph edges; spec 236 FR-014a says a reader "MUST be used only for the graph scope its proof covers"
  (`specs/236-arno-callout-adoption/spec.md:268-272`). The sources disagree on what the library reads:
  `CHANGELOG.md:1103-1105` and `ArnoAccel.cls:255-257` say it reads the `^NKG` export (graph-blind);
  `tests/unit/test_411_arno_kg_readers.py:1-17` says the readers walk `^KG("out",0,...)`;
  `specs/236-arno-callout-adoption/research.md:165-170` says USER's `^KG`.
- Impact: with arno-callout 1.2.1 (pagerank, revision 2) loaded in USER, `kg_PAGERANK()` on a namespace where a named
  graph has edges is answered by a reader whose graph scope was never proven. If it reads the `^NKG` export, the answer
  is every graph merged (SYS-I2), and it is then cached under the default graph.
- What would close it: route to a native reader only when `named_graph_with_edges()` is None (as BFS and the `^NKG`
  tiers do), or add a named-graph fixture to the gate and record graph scope in the proof; a live test with a named
  graph's edges and the library loaded.

### F-1002 `random_walk` needs the Arno library for an ObjectScript walk, and walks every graph's edges
- Statements: ALG-B9.9, ALG-I1, ALG-I3, ALG-I5.
- Evidence: `random_walk` calls `Graph.KG.NKGAccel.RandomWalkJson` only when `_detect_arno()` is true and otherwise
  returns `[]`, also on any failure (`iris_vector_graph/_engine/algorithms.py:658-678`). `RandomWalkJson`
  (`iris_src/src/Graph/KG/NKGAccelTraversal.cls:187-222`) is pure ObjectScript: it reads `^NKG(-1, idx, ...)` with no
  graph check, no `EnsureNKG` and no `RefuseMergedGraphs`; its other branch reads the legacy unsharded
  `^KG("out", node, ...)` layout, which holds nothing in production (`NKGAccelTraversal.cls:1-8`).
- Impact: without the library the call answers `[]`, against "IVG answers the same without it" (`CONTEXT.md:261-264`).
  With it, once a named graph has edges, a walk from a default-graph node can step along a named graph's edges of a
  node with the same id (`CONTEXT.md:97-101`), silently. After an erase has marked `^NKG`, it reads the dropped
  snapshot without rebuilding.
- What would close it: decide HD-1001; at least call `EnsureNKG` and refuse (or walk `^KG` graph 0) when a named
  graph has edges; a live test with two graphs sharing a node id.

### F-1003 Global PageRank lists at most 10,000 nodes from its owner and every node from the native reader
- Statement: ALG-B1.11.
- Evidence: `PageRank.PageRankGlobalJson` stops writing rows at `count >= 10000`
  (`iris_src/src/Graph/KG/PageRank.cls:506-520`); the native answer is ranked with `_ranked_rows(..., 0)`, which keeps
  every row (`iris_vector_graph/stores/iris_sql_store.py:124-129`, `2396-2399`). The method's docstring says every node
  takes part and the scores sum to 1 over `node_count()` nodes (`_engine/algorithms.py:741-760`); no guide mentions a
  cap.
- Impact: on a default graph of more than 10,000 nodes the answer's length and its sum depend on whether the library is
  loaded. The gate's five fixtures are small, so `scores_equivalent` (which compares node sets) cannot see it.
- What would close it: decide HD-1004; make both routes cut (or not cut) the same way and document it.

### F-1004 A cached personalized PageRank answer misses a start node written or removed without an edge
- Statements: ALG-B2.19, ALG-I4, ALG-B16.11.
- Evidence: `execute_ppr`'s cache key holds the start nodes and the walk's settings only
  (`iris_vector_graph/stores/iris_sql_store.py:2248-2258`). The owner reads whether each start node is a node of the
  graph from the node table (`NodeSeeds`, `iris_src/src/Graph/KG/PageRank.cls:87-116`). A node written without an edge
  moves no adjacency token; the store says so and adds a node-table token to global PageRank's key for that reason
  (`iris_sql_store.py:2362-2370`, `_engine/algorithms.py:179-193`, 4.6.0 R313).
- Impact: `kg_PERSONALIZED_PAGERANK(["x"])` before `x` exists caches an empty answer; after `create_node("x")` with no
  edge the same call still answers `{}` where networkx scores `x` 1.0. Deleting an edgeless start node leaves the old
  answer, which still lists it.
- What would close it: put the node token in the PPR key (and in any cached algorithm whose answer reads the node
  table), or bump the token on node writes; a live test.

### F-1005 The interned snapshot can lack edges with nothing saying it is out of date
- Statement: ALG-B12.7.
- Evidence: `Graph.KG.Adjacency.PutShadow` writes a temporal edge's structural shadow to `^KG` and raises the token
  but never interns it into `^NKG` (`iris_src/src/Graph/KG/Adjacency.cls:111-140`; documented as the adjacency
  contract in `iris_vector_graph/_engine/temporal.py:280-286`). `EnsureNKG` checks only the invalidated and stale marks
  (`TraversalBuild.cls:399-424`); nothing compares `^NKG("$meta","builtFrom")` with `^KG("__version")`, and
  `iris_vector_graph/freshness.py` defines `NKG` (lines 29-30) but no reader calls it.
- Impact: betweenness, closeness, eigenvector, the Leiden server route, neighbourhood betweenness, the `^NKG`
  procedures and the Arno BFS answer without those edges, while PageRank, WCC, CDLP and the ObjectScript BFS (over
  `^KG`) include them. `CONTEXT.md:109-114` and SYS-I8 say a rebuilt store matches its sources or says it is stale.
- What would close it: mark `^NKG` stale on `PutShadow` (EnsureNKG then rebuilds), or state the exclusion on every
  `^NKG` method; a live test with one temporal edge.

### F-1006 Subgraph vectors are read by node id in every graph
- Statement: ALG-B8.4.
- Evidence: `_subgraph_embeddings` selects from `kg_NodeEmbeddings WHERE node_id IN (...)` with no `graph_id`
  (`iris_vector_graph/_engine/algorithms.py:850-880`); the table is keyed `(graph_id, node_id)`
  (`iris_vector_graph/schema.py:429-437`); the walk is the default graph's (`Subgraph.cls:6-11`). The method's comment
  says `Graph.KG.Subgraph` is namespace-wide, which it is not.
- Impact: where `kg_NodeEmbeddings` holds a named graph's row for an id the default graph also holds,
  `include_embeddings=True` can return the named graph's vector (the dict keeps whichever row comes last). Named graphs
  normally keep vectors in their own route table (`docs/KNOWN_ISSUES.md:702-714`), so this needs such a row; not
  checked live.
- What would close it: add `graph_id = ''` to the read, fix the comment, and test with two graphs.

### F-1007 Degree centrality counts parallel edges on out-edges but not on in-edges
- Statement: ALG-B5.4.
- Evidence: `DegreeCentralityJson` counts out-degree with `Graph.KG.Adj.Degree`, which counts a keyed triple's `"#"`
  edges, and in-degree by `$Order` over `^KG("in", g, node, p, s)`, one per source
  (`iris_src/src/Graph/KG/Centrality.cls:88-139`); the `"#"` count lives only under `^KG("out")`
  (`Adjacency.cls:203-206`, `255`).
- Impact: in multigraph mode, three parallel `a->b` edges give `a` out-degree 3 and `b` in-degree 1, and `"both"` mixes
  the two rules. `CONTEXT.md:103-108` says parallel edges each count towards degree.
- What would close it: count in-degree from the out mirror's multiplicity; a multigraph test.

### F-1008 Variable-length expansion's every-graph mode walks across graphs
- Statement: ALG-B11.2.
- Evidence: with `pAll = 1` (the signature's default), `VarLength.Setup` puts every graph key in `pGraphs`
  (`iris_src/src/Graph/KG/VarLength.cls:44-51`) and `Adjacent` reads a node's edges in every graph
  (`VarLength.cls:126-148`), so one walk can take an edge of graph A and then an edge of graph B from a node with the
  same id. The translator still passes `gall = 1` for an all-graphs read whose source is not a correlated `n.node_id`
  column (`iris_vector_graph/cypher/translator.py:15404-15428`); its own comment calls the cross-graph walk a defect.
- Impact: such a query can return ends that no single graph reaches (`CONTEXT.md:38-43`). Which Cypher shapes reach
  the `gall = 1` branch was not established here.
- What would close it: walk each graph separately in the every-graph mode; a live test with a parameter source.

### F-1009 `khop` answers a start node that exists only in a named graph
- Statement: ALG-B9.5.
- Evidence: the walk is the default graph's (`BFSFastJson(seed, "", hops, "", "out")`, graph defaulted;
  `iris_vector_graph/_engine/algorithms.py:600-606`), but `_khop_seed_exists` counts `node_id` in every graph
  (`algorithms.py:619-626`).
- Impact: `khop("x")` for an `x` held only by graph `g` answers `{"nodes": ["x"], "edges": []}` where the docstring
  promises two empty lists for a missing seed.
- What would close it: add `graph_id = ''` to the count.

### F-1010 Leiden's server route ignores `max_levels` and `tol`
- Statement: ALG-B6.4.
- Evidence: `_leiden_serverside` sends `LeidenJsonAuto(10, gamma, 0.0001, top_k, 256, seed)` whatever the caller asked
  (`iris_vector_graph/stores/iris_sql_store.py:3765-3790`); `LeidenJsonPy` takes neither
  (`iris_src/src/Graph/KG/Communities.cls:615`, `698-703`), and `LeidenJson` documents `tol` as unused
  (`Communities.cls:433-443`).
- Impact: `leiden_communities(max_levels=2)` answers as if 10 levels were allowed whenever the snapshot route runs.
- What would close it: pass the caller's values, or document that this route ignores them.

### F-1011 Documents describe snapshot behaviour the code no longer has
- Statements: ALG-B6.6, ALG-B12.9.
- Evidence: `docs/ADMIN_GUIDE.md:1272-1273` says "Algorithms answer `[]` for every node. `^NKG` is not built"; the
  methods fall back to a Python walk with a warning (`iris_sql_store.py:3326-3335`) or raise (`CHANGELOG.md:1009-1017`).
  The `triangle_count`, `strongly_connected_components` and `k_core` docstrings say they read `^NKG` while only the
  default graph has edges (`_engine/algorithms.py:1676-1684`), but their store methods use the Arno upload of `^KG`
  graph 0 or LazyKG (`iris_sql_store.py:3977-4006`).
- Impact: an operator chasing empty answers is sent to `sync()`; a reader of the docstrings expects `^NKG` speed and
  scope.
- What would close it: update the troubleshooting entry and the three docstrings.

### F-1012 The proof record names one library build for entries proven on different builds
- Statement: ALG-B15.9.
- Evidence: `build_proof` keeps an earlier entry for any algorithm absent from the run but writes the current run's
  `version` and `sha256` as the record's only library (`iris_vector_graph/_arno_gate.py:138-177`); `CONTEXT.md:276-280`
  says the record holds the build each reader was proven on. `tests/unit/test_236_reader_gate.py::test_an_algorithm_not_rerun_keeps_its_earlier_record`
  (unit) asserts the keeping, not the build name.
- Impact: after a partial gate run on a new build, an entry proven on the old build reads as proven on the new one.
- What would close it: keep the library identity per entry.

### F-1013 `Graph.KG.PageRankEmbedded` is deployed and reads every graph
- Statement: none (no engine method calls it); recorded for scope.
- Evidence: `ComputePageRankCore` selects `nodes` and `rdf_edges` by `node_id LIKE ?` with no `graph_id` predicate and
  unqualified table names (`iris_src/src/Graph/KG/PageRankEmbedded.cls:5-30`); the class is deployed
  (`docs/ADMIN_GUIDE.md:346`) and called by `scripts/deploy_objectscript.py:129`.
- Impact: a direct caller gets every graph's nodes and edges merged, or a table outside the IVG schema.
- What would close it: remove the class or scope it to one graph and the IVG schema.
