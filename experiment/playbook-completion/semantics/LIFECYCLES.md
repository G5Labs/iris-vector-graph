# Canonical lifecycles (playbook 3.3a step 3)

Product pin `3eaa79cf`. Semantics lane, steer 7. The canonical lifecycles are defined in `lifecycles.json`; the per-object
mapping (every ontology entity's states and commands onto one lifecycle) is in `objects.json`, generated by
`semantics/tools/build_semantics.py` from the hand mapping `src/objects_map.json`. The objects are the 62 `Entity` lines of
`ontology/[0-9]*.md` (module 00 declares none), derived mechanically; an object's id is its two-digit module, a slash and
its entity name lowercased with spaces as hyphens.

Rules of the mapping. One name and one meaning per canonical state and command, within its lifecycle. Each ontology state
maps to one canonical state; a state that is a mode, a setting value or a property orthogonal to the lifecycle maps to a
canonical state with a **facet** (the playbook's approval and block are facets, not states). Each ontology command maps to
one canonical command, read as what that command is for this object (a write of an edge is `maintain` for a cache entry).
Canonical ids are scoped by lifecycle: `current` in LC-2 (equals its derivation) and `current` in LC-3 (in force) are two
states, written LC-2/current and LC-3/in-force where the difference matters (see the collisions section).

## LC-1 Content item

A piece of graph content a caller writes: a node, edge, label, property, qualifier, temporal event, vector, text document or reifier, in one graph.

| State | Meaning |
|---|---|
| `absent` | no store holds the item in its graph |
| `live` | some primary store holds the item in its graph (SYS-D13) |

| Command | Meaning |
|---|---|
| `create` | make the item live (also store, insert, merge-create, bulk create) |
| `update` | change a live item's value (set, reweight, replace, merge-match) |
| `delete` | make one item absent by its id |
| `erase` | make every item of a graph or id prefix absent (module 12) |
| `read` | answer from the item without changing it |
| `restore` | bring the item back from an archive (module 18) |

Facets: governed (the ledger records it); marked (implied by a temporal write, ADR-0009); shared id (the same id is live in another graph); parallel (multigraph); orphan (outlived the item it depends on); rolled back (an open writer's write was undone).

Composed from mechanisms: M-01, M-09, M-10, M-05 (see `MECHANISMS.md`).

Objects (8): `03/edge-in-one-graph`, `03/node-in-one-graph`, `05/temporal-coordinates`, `05/triple-row`, `08/cypher-edge`, `08/cypher-node`, `11/node-id`, `15/reifier`.

## LC-2 Derived entry

A store or entry computed from other stores: an index, a cache entry, a compiled plan, a statement map, an aggregate.

| State | Meaning |
|---|---|
| `absent` | not built |
| `building` | a build or upgrade is in progress |
| `current` | equals its derivation from the committed source (stamp equals token) |
| `stale` | known not to equal its derivation; readers must not trust it |
| `build-failed` | a build failed; readers fall back to the source |

| Command | Meaning |
|---|---|
| `build` | compute from the source and stamp it |
| `maintain` | a source write that updates the entry in its transaction or marks it stale |
| `read` | answer from the entry after checking its signal |
| `rebuild` | recompute from the source, replacing the entry |
| `drop` | remove the entry |
| `upgrade` | move the entry to a newer layout |

Facets: layout version (e.g. BM25 schema 1 or 2); degraded (written without its lock, with a mark).

Composed from mechanisms: M-04, M-12, M-03 (see `MECHANISMS.md`).

Objects (12): `04/adjacency-entry`, `04/degree-cache-entry`, `04/no-lock-mark`, `04/result-cache-entry`, `05/latest-event-index`, `06/ivf-index`, `07/bm25-index`, `09/compiled-shape`, `10/interned-snapshot`, `10/result-cache-entry`, `11/edge-statement`, `17/index-handle`.

## LC-3 Setting or install

A configuration of a namespace, a graph, a process or a deployment: the install, the class set, the ledger state, a graph's mode, a route registration, an optional dependency.

| State | Meaning |
|---|---|
| `absent` | not set up or not present |
| `in-force` | set up and in force |
| `outdated` | present from an earlier release or setup; needs an upgrade or forced setup |
| `partial` | a setup started and did not finish |
| `broken` | present but unusable or in conflict (another schema, another app, a bad value) |
| `disabled` | set up and switched off |

| Command | Meaning |
|---|---|
| `setup` | create or bring in force (deploy, setup, register, create web app, map) |
| `set` | change one value of a setting in force (turn on/off, set strict, set mode) |
| `upgrade` | move from outdated to in force (forced setup, migration, adopt) |
| `remove` | take the setting or install away (legacy removal, unmap, drop) |
| `read` | report the setting (status, info, preview, list) |
| `consult` | run a command that depends on the setting (first use, a call under the mode) |

Facets: strict (ledger); read-only role; edition (Community without %AI); mode value.

Composed from mechanisms: M-08, M-11, M-12 (see `MECHANISMS.md`).

Objects (20): `01/class-set`, `01/legacy-object`, `01/namespace`, `01/setup-routine`, `02/graph-mode`, `03/ledger-state`, `05/edge-type-in-a-graph`, `06/registry-row`, `06/route`, `09/engine-native-path`, `09/process-mode`, `10/native-route`, `11/ledger`, `15/fhir-graph`, `15/rdf-extra`, `15/table-mapping`, `16/mcp-tool-set`, `16/rest-web-app-path`, `17/namespace`, `18/namespace`.

## LC-4 History item

An item of the revision ledger: a revision, a record, a retry-key binding.

| State | Meaning |
|---|---|
| `absent` | not yet committed (a retry key: free) |
| `committed` | saved in a revision and never changed since (a retry key: bound) |
| `tombstoned` | redacted: keeps its place, holds no content (a retry key: redacted) |

| Command | Meaning |
|---|---|
| `append` | append in a new revision |
| `replay` | a retry answered from the binding, with no effect |
| `redact` | turn into a tombstone |
| `read` | read history (history, records, diff, verify, export) |

Facets: kind (changeset, adoption, redaction).

Composed from mechanisms: M-01, M-02 (see `MECHANISMS.md`).

Objects (1): `11/retry-key`.

## LC-5 Run

Work that takes several steps or is done later: a queue entry, a redaction run, a sync, a build job.

| State | Meaning |
|---|---|
| `absent` | not requested |
| `pending` | requested and waiting for a worker |
| `running` | a worker is on it |
| `stopped` | interrupted, with its effects so far kept; can be resumed |
| `done` | finished with its result |
| `failed` | finished without its result, reported |

| Command | Meaning |
|---|---|
| `start` | request the work (enqueue, call, schedule) |
| `work` | a worker step |
| `stop` | interrupt (process stop, a bound reached, the ledger disabled) |
| `resume` | call again after a stop |
| `finish` | mark done or failed |
| `clear` | remove finished entries |
| `read` | report the state |

Facets: none.

Composed from mechanisms: M-07, M-03 (see `MECHANISMS.md`).

Objects (2): `06/queue-entry`, `13/redaction-run`.

## LC-6 Scope

A graph or a tenant target (a graph plus an optional id prefix) as a whole.

| State | Meaning |
|---|---|
| `empty` | no content and no history |
| `live` | holds content |
| `erasing` | an erasure is open on it |
| `erased` | no content; history still holds its records |
| `redacting` | a redaction run is open on it (marker set) |
| `redacted` | no content and its history is tombstoned |

| Command | Meaning |
|---|---|
| `write-into` | a commit or direct write of content into the scope |
| `erase` | remove the scope's content from every store |
| `redact` | remove the scope's content from history |
| `read` | a read or verify of the scope |

Facets: default graph or named graph; with unrecorded writes.

Composed from mechanisms: M-05, M-03, M-09 (see `MECHANISMS.md`).

Objects (4): `12/graph-content`, `13/redaction-target`, `14/ledger-view`, `16/graph-a-caller-names`.

## LC-7 Session, request or claim

Something held for a while by one caller: a transaction, a reader handle, a Bolt session, an HTTP request, a connection, a lock.

| State | Meaning |
|---|---|
| `new` | created, not yet accepted (not logged in, not begun) |
| `open` | in use by its holder |
| `closed` | ended normally; its outcome was delivered |
| `refused` | ended by an explicit refusal before any effect |
| `errored` | ended by an error; its effect may be unknown |

| Command | Meaning |
|---|---|
| `open` | begin, log in, connect, take the lock |
| `use` | a step inside it (run, read a page, write) |
| `commit` | end keeping its writes |
| `rollback` | end dropping its writes |
| `close` | end it, release what it holds |

Facets: read-only; shared or exclusive (a lock); link kind (client, inside IRIS).

Composed from mechanisms: M-10, M-11, M-03, M-13 (see `MECHANISMS.md`).

Objects (11): `03/caller-transaction`, `04/graph-writer-lock`, `05/reader-handle`, `07/fused-search`, `08/cypher-call`, `10/default-graph-algorithm-call`, `11/caller-transaction`, `16/bolt-session-with-a-key-set`, `16/cypher-http-call`, `17/client-request`, `17/link`.

## LC-8 Copy

A copy of content kept outside the live stores: a snapshot archive, a quarantined vector.

| State | Meaning |
|---|---|
| `absent` | no copy |
| `kept` | the copy exists and holds content |
| `released` | the copy was placed back or restored and no longer holds what it released |

| Command | Meaning |
|---|---|
| `save` | make the copy |
| `restore` | put the copy's content back (replacing or merging, or placing a quarantined row) |
| `read` | report on the copy |
| `discard` | delete the copy |

Facets: layout version.

Composed from mechanisms: M-06, M-05 (see `MECHANISMS.md`).

Objects (2): `06/quarantined-row`, `18/snapshot-archive`.

## What the canonical states show

Mapping onto one vocabulary makes some gaps visible (each is already a finding or a mechanism departure in `MECHANISMS.md`):

- `06/ivf-index` and `07/bm25-index` declare no LC-2/stale state, although vector writes, erasure and node text changes do
  not maintain them (F-0606, F-0703): the ontology's states match the pin, which has no staleness signal there (M-04).
- `06/queue-entry` declares no LC-5/running state: neither worker claims an entry (F-C0601, F-C0605; M-07).
- `11/retry-key` declares free and bound only; the pin also has the redacted binding (`idemRedacted`, LC-4/tombstoned),
  which the entity line omits.
- `15/reifier` has an `orphan` state (LC-1/live with facet orphan): content that outlived what it depends on, which AX-10
  forbids (F-1502). `06/quarantined-row` keeps a held row through `erase graph`, whose canonical command is LC-8/discard
  (F-C1305).
- LC-4 has one ontology entity (`11/retry-key`): revisions and records are not entities of the ontology; their lifecycle is
  still LC-4, through M-01 and M-02.

### Collisions in the canonical vocabulary itself (resolved)

The first draft of `lifecycles.json` reused ids with different meanings: state `current` (LC-2: equals its derivation;
LC-3: in force), state `failed` (LC-2: a build failed; LC-5: a run finished without its result; LC-7: ended by an error),
command `use` (LC-3: a command that depends on the setting; LC-7: a step inside a session). They were renamed so that one
name has one meaning across the whole vocabulary: LC-3 `current` -> `in-force`, LC-3 `use` -> `consult`, LC-2 `failed` ->
`build-failed`, LC-7 `failed` -> `errored` (LC-5 keeps `failed`); the checker's vocabulary rule then found LC-4 `commit`
(append in a new revision) against LC-7 `commit` (end a transaction keeping its writes), so LC-4's is now `append`. Ids that
still recur mean the same thing everywhere, seen from two levels: `absent` (no instance exists), `read` (answer or report
without changing anything), `restore` (put archived content back into the live stores, seen from the item in LC-1 or from
the copy in LC-8), `erase` (remove every item of a scope, seen from the item in LC-1 or from the scope in LC-6), `live`
(SYS-D13: some store holds the content, of an item in LC-1 or of a scope in LC-6), `upgrade` (bring to the current
release's layout or setup, LC-2 and LC-3) and `redact` (turn history into tombstones, of a record in LC-4 or of a scope in
LC-6). `semantics/tools/check_semantics.py` rejects a state or command id that two
lifecycles define with different meaning texts unless it is one of these seven.
