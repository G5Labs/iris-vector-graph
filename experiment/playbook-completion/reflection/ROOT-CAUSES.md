## Corpus and rule

- Each finding has exactly one **primary** root cause; **secondary** causes are listed where another rule is also broken. Refuted, not-reproduced and duplicate findings are listed separately and count to no root cause (6). Intent-undecided and blocked-access findings are assigned but marked *conditional* (8): the behaviour is observed or confirmed in source, the intent or the live reproduction is not settled.
- A root cause is a missing or violated shared rule or mechanism. 'Violates' names the original ontology's universal axioms SYS-I1..SYS-I10 (`experiment/playbook-uplift/ontology/00-system.md`) where one applies, and otherwise the playbook principle or product document it breaks.
- Cross-reference to the semantics lane (`semantics/axioms.json`, `semantics/mechanisms.json`): final ids: each root cause names the axioms (AX-NN) it violates and the mechanism (M-NN) its remedy needs; member_classes counts the semantics lane's own classes of its members. The checker verifies every AX/M id against the final files; 'agreeing' counts the members the semantics lane itself classed under one of the root cause's axioms (an independent classification of the same findings, `semantics/src/finding_classes.json`).

## Top 10 (findings covered, then severity)

1. **RC-01 Graph scope is added by hand to each statement** — 22 findings (12 S1, 7 S2, 3 S3), highest S1. Remedy: Route every read and write through one graph-scoped access layer whose statements always bind graph_id (default '') and join on (graph_id, id); refuse unscoped calls; give every reader's tests a two-graph fixture with one id held by both graphs.
2. **RC-33 Stated refusals, options and protocol verbs are accepted and ignored** — 18 findings (6 S2, 8 S3, 4 S4), highest S2. Remedy: Audit every documented refusal, parameter and protocol verb mechanically (a list generated from the docs and specs), implement it or refuse it with a named error, and test each.
3. **RC-14 Failures are swallowed into empty, default or success answers** — 17 findings (7 S2, 6 S3, 4 S4), highest S2. Remedy: Enforce the 4.6.0 rule mechanically: no handler returns an empty/default answer from an except clause; every outcome (removed, DONE, restored counts, health, legs used) is computed from the operation's own result; a lint over except clauses plus a fault-injection test per reader.
4. **RC-31 Descriptions are written by hand and not checked against the code** — 16 findings (13 S3, 3 S4), highest S3. Remedy: Generate or test every description: execute documentation examples (tests/docs), check spec and ADR status lines in CI, generate the wire schema, constraint lists and status parts from the code, and keep evidence claims tied to commits of this repository.
5. **RC-16 The Cypher and AQL translators have no reference semantics** — 13 findings (1 S1, 6 S2, 5 S3, 1 S4), highest S1. Remedy: Drive the translators from a reference semantics: the typed openCypher TCK at the pin on every supported engine, a differential oracle per clause shape against a reference evaluator, and a refusal for every shape outside the covered set.
6. **RC-03 Removal reach is not derived from a declared store inventory** — 12 findings (6 S1, 3 S2, 3 S3), highest S1. Remedy: Declare one store inventory (each store and field with its owning graph/tenant key and its erase, redact, export and liveness hooks) and generate erasure, LiveRows/Matches, the snapshot plan and the receipt's out_of_reach list from it; check mechanically that every writer's target store is in the inventory.
7. **RC-10 A command's writes are not one validated, all-or-nothing unit** — 12 findings (9 S2, 2 S3, 1 S4), highest S2. Remedy: One write-transaction wrapper used by every entry point: validate the whole request first, then perform every write of the command in one transaction (nesting with TROLLBACK 1), never committing inside it; a failure test per entry that asserts no store changed.
8. **RC-12 Environment premises are asserted, not validated** — 12 findings (4 S2, 5 S3, 3 S4), highest S2. Remedy: An executable environment contract for every supported (engine, edition, driver, optional library) cell, run in CI, plus run-time capability probes that refuse with a named reason instead of assuming; a driver floor in pyproject.toml with a refreshed uv.lock.
9. **RC-06 Derived stores and caches have no reliable staleness signal** — 11 findings (8 S2, 1 S3, 2 S4), highest S2. Remedy: One staleness mechanism for every derived store: a monotonic per-graph epoch stepped before every source write on every path and never killed, recorded at build and compared at read; mark the derived store stale on rollback, or store a computed answer only when the writer lock was free and the epoch did not move.
10. **RC-23 Results depend on storage order or join multiplicity** — 11 findings (1 S2, 3 S3, 7 S4), highest S2. Remedy: Order every result prefix and every allocation by a total key, use EXISTS for filters, and close the storage-order scan's candidate list (order or document each).

### RC-02 Stored facts whose key omits the graph

- Statement: Several stores key a fact without its graph: ledger node records (genesis and LedgerApply record nodes graph-blind), reifier nodes (always the default graph), BM25 and IVF indexes with no recorded graph, edge vectors in a snapshot. Ownership checks built on them (redaction's targets, liveness, verify(), node-delete existence, index use under a graph) cannot attribute the fact, so they attribute it to the default graph or to every graph.
- Violates: SYS-I2; SYS-D3 (each piece of data belongs to one graph); ADR-0013/plan.md:9-10 (node records are graph-blind by design).
- Highest severity S1; modules 06, 07, 11, 13, 14, 15, 18.
- Semantics lane: axioms AX-02, AX-01; mechanism M-09, M-12; 8 of 8 members classed under one of these axioms by the semantics lane; its classes of the members: AX-02 8, AX-07 1, AX-10 2, AX-12 2.
- Remedy (prose only): Make the graph part of every stored key: record each node record's graph, create reifiers in the edge's graph, record the graph of every derived index and archive row; treat an absent graph as unknown (refuse or report incomplete), never as the default graph.
- Findings (8):
  - F-0609 [S2, confirmed-source] The fused search may read an IVF index built for another graph
  - F-0705 [S1, reproduced-live] An index with no recorded graph is read as the default graph's own index
  - F-1105 [S2, reproduced-live] Deleting a node that only a named graph holds records a delete that removed nothing
  - F-1304 [S1, reproduced-live] An unprefixed default-graph redaction tombstones history of nodes live in a named graph
  - F-1305 [S1, reproduced-live] A graph-per-tenant redaction with unprefixed ids reports success while the tenant's node history remains
  - F-1401 [S2, reproduced-live] verify() reports divergence after a logged detach-delete involving named-graph edges
  - F-1502 [S1, reproduced-live] A reifier node always lands in the default graph, and erasing the edge's graph leaves it (with its properties) live
  - F-1803 [S2, reproduced-live] Edge vectors lose their graph and metadata in a snapshot
- Also a secondary cause of: F-0606, F-0611, F-0707, F-C1547

### RC-04 Erase, ledger commits and redaction start are not serialized on the ledger head lock

- Statement: The eraser deletes rows and kills statement-map entries without ^IVG.Ledger("head"); redaction reads its 'another run?' check and its liveness check unlocked and READ UNCOMMITTED and sets its marker only with the first tombstone; adoption and the first enable read the state they decide on before taking the lock. Each is a check-then-act on ledger-owned facts that a concurrent commit, erasure, rollback or second run invalidates.
- Violates: SYS-I1, SYS-I3; LED-B4.14.4 (only the head-lock holder changes the statement maps); RED-B1.1 (never tombstone live content); premises P-1311, P-C01, P-A3 (false at the pin).
- Highest severity S1; modules 11, 12, 13.
- Semantics lane: axioms AX-11; mechanism M-03; 10 of 10 members classed under one of these axioms by the semantics lane; its classes of the members: AX-01 1, AX-08 1, AX-11 10, AX-12 1.
- Remedy (prose only): Serialize erase, ledger commits, adoption, enable and redaction start on the head lock (HD-1201 and HD-1301 working answers): take the lock before reading what a step decides on, check liveness against committed state and set the per-target marker in the same locked step, run the eraser's row deletes and statement cleanup under the same lock, and let Final act only when its scan reached the head it holds.
- Findings (10):
  - F-1103 [S2, reproduced-live] An adoption is not tied to the head it compared
  - F-1104 [S3, reproduced-live] Two first enables at once: the second fails instead of returning the genesis
  - F-1114 [S1, reproduced-live] Erasure changes the statement maps without the head lock
  - F-1201 [S2, reproduced-live] A graph erasure removes the statement entry of an edge a concurrent ledger commit creates
  - F-1302 [S1, reproduced-live] Redaction can tombstone history of content a concurrent commit made live (unlocked start, late marker)
  - F-1303 [S1, reproduced-live] Concurrent redactions of two targets mix their audit counts and one removes the other's marker
  - F-C1201 [S1, reproduced-live] A redaction can complete against an erasure that is still open and then rolls back
  - F-C1202 [S2, reproduced-model] EraseGraph's adjacency kill can drop the adjacency of an edge committed after its row delete
  - F-C1301 [S1, reproduced-live] The redaction liveness check reads any writer's uncommitted delete
  - F-C1302 [S2, reproduced-model] Final trusts a scan that ended before it took the lock
- Also a secondary cause of: F-C1307, F-C1350, F-C1351

### RC-05 Unlocked read-modify-write of shared facts outside the ledger

- Statement: Outside the ledger, writers of shared facts read, decide and write with no lock, or under a lock mode that excludes nothing: multigraph mode off vs a parallel-edge write, BM25 Build/Drop, adjacency rebuilds (shared ^IVG.AdjW), native-plan DropAll vs Build, embed-queue claims, ledger_stats counters (%OpenId/%Save), snapshot file names.
- Violates: SYS-I1; playbook §1 principle 3 (concurrency control lives in the database; lock plans are proved per handler).
- Highest severity S2; modules 02, 03, 04, 06, 07, 09, 11, 18.

- Remedy (prose only): Give every handler a lock plan: each read-modify-write of a shared fact holds the owner's exclusive lock across the read and the write, or uses an atomic primitive ($Increment, unique names, a version-checked write); one two-process interleaving test per handler.
- Findings (10):

  - F-0701 [S2, reproduced-live] BM25 Build and Drop write without the write lock or a transaction

  - F-1102 [S3, reproduced-live] The stats row can lose counts
  - F-1807 [S3, reproduced-live] The HTTP snapshot endpoint can write two snapshots to one path

  - F-C0402 [S2, intent-undecided] Two adjacency rebuilds can run at once *(conditional: intent-undecided)*
  - F-C0601 [S3, reproduced-model] A node re-enqueued while a worker holds its old text is marked DONE with the old vector

### RC-06 Derived stores and caches have no reliable staleness signal

- Statement: Caches and rebuilt stores (degree cache, algorithm cache, BM25 indexes, the interned snapshot ^NKG, temporal bucket aggregates, an engine's multigraph-mode cache) are kept current by a token or generation that is stepped after the write, killed and restarted, not stepped on every path (weights, node-only writes, temporal writes), survives a rollback ($Increment), or is not consulted at all, so a derived answer stays 'current' after its source changed or rolled back.
- Violates: SYS-I8; CONTEXT.md:109-120 (graph-version token); ADR-0012; AlgoCache.cls:5-7 ('never wrongly fresh').

### RC-34 Stores have no enforced single write owner

- Statement: Outside the ledger, stores owned by one module are written directly by others: ^KG("prop") has no owner and four writers, the Arno bridge moves the adjacency token, the vector module kills a sub-store of ^NKG, the Cypher DELETE and the SQL adapter delete vector, document and reification rows themselves, the FHIR build writes the label index and vector rows, a loader clears content tables by raw SQL. Each direct writer skips the owner's rules (routes, tokens, graph scope, strict mode).
- Violates: SYS-I1; playbook §3.4 (each store has a single write owner); ADR-0011 (one adjacency writer); module Scope sections of the ontology.
- Highest severity S3; modules 03, 04, 06, 08, 10, 15, 17.
- Semantics lane: axioms AX-01; mechanism M-12; 7 of 7 members classed under one of these axioms by the semantics lane; its classes of the members: AX-01 7, AX-02 1, AX-07 1, AX-10 1.
- Remedy (prose only): Name one owner per store (as GraphStores.Inventory does for erasure) and route every other writer through the owner's method; a mechanical census (as the structural lane's st-check-own-census) that fails on a write to a store outside its owner.

  - F-C0640 [S4, confirmed-source] Dropping a neighborhood_vector index handle kills ^NKG("q") in the interned snapshot
  - F-C0840 [S3, confirmed-source] A Cypher DELETE deletes vector rows and reification rows itself, and only from the legacy vector table
  - F-C1040 [S4, confirmed-source] Graph.KG.ArnoAccel.BumpVersion moves the adjacency module's graph-version token

### RC-35 Bulk loads bypass the indexes and key checks every other path relies on

- Statement: BulkLoader writes with INSERT %NOINDEX %NOCHECK by default: the rows it writes are in no index and pass no unique check until the indexes are rebuilt. Readers, the liveness check, erasure and the key invariants all read through those indexes, so duplicate keys are stored, a mode-off graph holds parallel rows, erasure leaves the loaded edge, and redaction completes while the tenant's loaded rows exist.
- Violates: SYS-I8, SYS-I1; schema.py:34-44, 396-419 (unique keys); GID-I4.10; spec 256 FR-005 (refuse while any row of the target is live); ADR-0004.
- Highest severity S1; modules 03, 12, 13.
- Semantics lane: axioms AX-08, AX-01; mechanism M-04; 2 of 4 members classed under one of these axioms by the semantics lane; its classes of the members: AX-01 2, AX-02 1, AX-10 2, AX-11 1.
- Remedy (prose only): Make the bulk loader leave the indexes current before it returns (rebuild inside the load, or no %NOINDEX on key-carrying tables) and drop %NOCHECK for unique keys; until then refuse erasure and redaction while an index build is pending.
- Findings (4):
  - F-C0349 [S2, reproduced-live] The bulk loader writes duplicate node, label, property and edge keys: an id twice in one batch, a load with skip_existing=False, or two loaders at once
  - F-C0350 [S2, reproduced-live] BulkLoader.load_edges' INSERT %NOINDEX %NOCHECK lets a graph whose mode is off hold two rows of one triple at the same edge key, and the index rebuild accepts them
  - F-C1250 [S1, reproduced-live] An rdf_edges row a %NOINDEX bulk load wrote survives delete_nodes_by_prefix of both its endpoints and EraseAll+PurgeAll until the indices are rebuilt; its endpoint nodes are deleted under it
  - F-C1351 [S1, reproduced-live] The redaction's liveness check misses rows a bulk load wrote with %NOINDEX: the redaction completes while the tenant's rows exist, and they reappear at the next index rebuild

### RC-36 Server answers are hand-encoded text decoded by patterns

- Statement: Several ObjectScript methods answer Python with hand-built text (comma lists, partly escaped JSON, shape-sniffed maps), and the Python side repairs or decodes it by text patterns: a leading-dot patch rewrites ids, comma splitting breaks names, an unescaped control character breaks the JSON, a node named 'components' is read as a summary.
- Violates: none of SYS-I1..SYS-I10; TXT-B2.13 (each id and score in the answer is valid JSON); RFC 8259 escaping (CHANGELOG.md:463-467); the decoders' own docstrings.
- Highest severity S2; modules 07, 10.
- Semantics lane: axioms AX-12; mechanism none; 0 of 4 members classed under one of these axioms by the semantics lane; its classes of the members: AX-03 1, FUNC 3.
- Remedy (prose only): One wire encoding for every server answer (%DynamicObject / JSON arrays built by the library, never by concatenation) decoded by json.loads only, with no text repair; a round-trip test with hostile names and ids.
- Findings (4):
  - F-C0715 [S2, reproduced-live] bm25_search rewrites document ids: its leading-dot patch runs over the whole answer, so an id holding ':.5', ',.7' or '[.9' comes back as ':0.5', ',0.7', '[0.9'
  - F-C0716 [S4, reproduced-live] The engine's index registry mis-decodes BM25Index.List: an index name holding a comma or a leading/trailing space is split or trimmed, so the real index is missing and phantom names appear
  - F-C0717 [S4, reproduced-live] BM25Index.Build and Info write the graph name into their JSON escaping only backslash and quote: a graph name with a control character makes bm25_build raise JSONDecodeError after the index was rebuilt, and the index's graph can no longer be read
  - F-C1018 [S4, reproduced-live] The store's membership decoder refuses the Owner's components and label-propagation answers when a default-graph node is named 'components', 'communities' or 'largest' (read as an accelerated summary); the engine masks it by calling the Owner a second time

## Limits

- The assignment is a judgement over the findings' recorded intended/observed/remedy text; another reader could place a borderline finding under a neighbouring cause (most such alternatives are recorded as secondary causes). The checker verifies coverage, existence and arithmetic, not the judgement.
- The corpus is read when the check runs: a finding any lane adds later fails `check_root_causes.py` until it is assigned (ratchet).
- Root causes are about the product's rules; whether the product's intent requires each rule is settled only where the findings' intent is (the conditional members are not).
