# Lock plans (gate 3.5-lockplans) for modules 01, 05, 06, 08, 10, 16, 17

Lane `lockplans`, pin `3eaa79cf`. Generated by `lockplans/render.py` from `lockplans/NN.json` (do not edit the tables
below by hand; edit the JSON and re-render). `python3 experiment/playbook-completion/lockplans/render.py --check`
verifies that every cited run is registered, every model check id exists and every finding id exists.

## Method

- **Obligations.** Per module, the writer entry points of `footprints/NN.json` are grouped by the lock plan they reach.
  An obligation is (entry-point group, conflict that must be excluded). Conflicts come from the module's ontology
  (`experiment/playbook-uplift/ontology/NN-*.md`), `semantics/MECHANISMS.md` / `AXIOMS.md`, `writesets/` and the
  product's own docs; each is cited. Locks, transactions and implicit SQL row locks the code takes are listed with
  path:lines in each module's lock inventory. Reading drafts for 01, 05, 06 and 10 are kept in
  `$RUN_DIR/lockplans/drafts/` (inputs, not evidence).
- **Verdicts.** `holds`: a live probe in the `correspondence/tools/lockplan.py` style (a probe connection holds a lock
  or a caller transaction, the product operation is observed to wait or not through `%SYS.ProcessQuery` and
  `%SYS.LockQuery_List()`, the journal as oracle), plus an explorer model where the claim is about interleavings.
  `violated`: a discriminating live interleaving (recorded as a finding in `findings/audit/zz-lockplans.json`) or an
  existing reproduced finding. `not-needed`: no conflicting writer, with the reason. `open`: predicted from source,
  model-only, unclear or blocked; the exact reason is in the row.
- **Live.** Namespace AUDITD only, identity-checked `tools/iris_conn.Conn`, under `tools/locks.sh iris`, at most 4
  connections; every script starts from the product's own `EraseAll` / `PurgeAll`. Probes: `lockplans/probes/`
  (`guarded_insert.py` 08/17, `conn_share.py` 16, `temporal_probes.py` 05, `nkg_probes.py` 10, `setup_probes.py` 01;
  shared `holdprobe.py`, `lpcommon.py`). Raw logs: `$RUN_DIR/lockplans/`.
- **Models.** `lockplans/models` (explorer at c03f9fa), families `guard_insert` (08, 17), `conn_mutex` (16),
  `tmp_conc` (05), `nkg_intern` (10), `setup_race` (01); each has an as-built variant, a reviewed variant (a statement
  about a model only) and a negative control the explorer must catch, plus sharpness checks. Results:
  `lockplans/models/RESULTS.json`; registered as `lockplans-mc-<family>-as-built`, `lockplans-mc-<family>-reviewed`,
  `lockplans-control-<family>`.
- **Levels.** Cells are proposed at level `product` from the as-built evidence. A reviewed model passing is never
  reported as the product satisfying the obligation.
