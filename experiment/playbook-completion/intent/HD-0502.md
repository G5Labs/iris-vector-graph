## Contradictions

- The glossary says temporal edges are subject to the revision ledger, which enables reconstruct and verify; reconstruct(head) omits a committed temporal edge and its record cannot rebuild weight, attrs or mode. (`CONTEXT.md:75`; `CONTEXT.md:193-196`; `iris_vector_graph/ledger/replay.py:170-208`; `live intent-a-hd0502-temporal-scope`)
- ADR-0009's amendment says nodes stay unless the purge is asked to retire them; since 4.7.0 purge_raw_before retires bare endpoints by default (and did so in strict mode, unrecorded, live). (`docs/adr/0009-...md:45`; `iris_vector_graph/_engine/temporal.py:656-679`)

## As built

A changeset temporal op is recorded (create_temporal_edge, entity id s|p|o@ts, value {s,p,o,graph}); weight (3.5), attrs and mode are not recorded. Replay/reconstruct/verify ignore temporal records and the temporal index. Engine temporal writes, delete_edge_temporal and purge_raw_before make no revision and are allowed in strict mode; the purge retired 4 endpoint node rows unrecorded.

Evidence: live `intent-a-hd0502-temporal-scope`; tested `tests/integration/test_ledger_us11_temporal_coexist.py:59-88`

## Intended contract

Settled: engine temporal writes (and purges) create no revisions (maintainer decision 43efd473, spec 213 US11). Not settled: whether a changeset temporal op is only an audit record or must be reproduced by reconstruct/verify; as built it is audit-only, while the glossary says 'subject to the revision ledger'. Status: assumption.

## Working assumption

Unchanged reading: record the changeset temporal op in history (audit, redaction); treat temporal tiers, engine temporal writes, purges and temporal replay as outside the structural replay guarantee; model their real effects, including purges deleting endpoint nodes.

## Alternatives

- (a) outside: audit trail only, and amend the glossary to say so
- (b) inside for changeset writes: records carry weight/attrs/mode; replay rebuilds and verify compares temporal edges
- (c) fully inside: ops for temporal delete/purge, engine temporal writes refused in strict mode

## Discriminating check

probe (run): `intent-a-hd0502-temporal-scope`. pass for the narrow reading: op recorded without weight/attrs/mode; reconstruct omits it; temporal delete/purge in strict mode allowed with no revision (purge retired 4 endpoint node rows).

## What would change this

A maintainer statement that 'subject to the revision ledger' means audit only (status becomes supported for (a)), or a requirement that reconstruct reproduce temporal edges (then (b)).

## Residual question for maintainer

Does 'subject to the revision ledger (via a Changeset temporal op)' promise only an audit record, or that reconstruct and verify reproduce temporal edges (which needs weight, attrs and mode in the record)? May purges delete node rows under strict mode without a record?

## Consequence rank hint

medium: affects what reconstruct/export claims for temporal data and whether purges silently change governed node rows.
