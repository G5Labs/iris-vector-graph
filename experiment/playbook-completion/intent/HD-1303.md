# HD-1303 Can an unfinished redaction be abandoned, and what may a default-graph target touch?

Question ([original](../../playbook-uplift/DECISIONS.md)): (a) A run stuck on a live target blocks every ledger write into it until the target is erased again; should an operator be able to abandon a run? (b) Should a default-graph target with no prefix count node rows of every graph, or be refused (F-1304)?

## Contradictions

- `plan.md:10 (graph-blind liveness for a default-graph target); LedgerRedact.cls:145-148 rationale` vs `LedgerRedact.cls:157-158 (no-prefix: default graph only) with Matches:93-94 (all node records match)`: redact(None) with no prefix is accepted while nodes recorded by the genesis live in a named graph, tombstones their history, and verify() diverges (live: ib-HD1303-nopfx-default).
- `ADR-0013:51 (marker removed in the final transaction)` vs `LedgerRedact.cls:415 (final step refuses and keeps the marker when the target became live)`: A stuck run keeps the target's name in plain text in ^IVG.Ledger("redacting") indefinitely, the opposite of the privacy purpose, until the target is erased again.

## As built

(a) No abandon or cancel operation; re-running the same target resumes; a target that became live makes the final step refuse (target_live) and keep the marker, so commits into the target are refused and other targets cannot start until the operator erases the target again; PurgeAll is the only other way out and destroys the whole ledger. (b) redact(None) without a prefix checks default-graph rows only and tombstones every node record, including nodes live in named graphs (genesis-recorded).

Evidence: live `ib-HD1303-nopfx-default`; inspected `iris_src/src/Graph/KG/LedgerRedact.cls:89-112, 143-178, 409-441`; live `original 9c3719c1 scenario default_graph_without_prefix`

## Intended

Status: **assumption** (by part: (a) assumption, (b) supported). (b) supported: the maintainer's plan (2b8ea46d, plan.md:10) makes the node-liveness check for a default-graph target graph-blind, and the code gives the reason (145-148); so a no-prefix default-graph target must be refused while any node row of any graph is live. (a) assumption: the only documented path is resume, and the maintainer's error text names the recovery (erase again, re-run); no source addresses abandoning a run whose tombstones are already committed.

## Working assumption

(a) No generic abandon: tombstones are irreversible, so 'abandon' could only remove the marker and accept a permanently divergent history; the recovery is re-erase and resume, and the docs should say that this also erases content re-created during the run. An explicit, audited cancel that records the partial redaction as a redaction revision is the alternative. (b) Apply the plan's graph-blind liveness check to every default-graph target, so redact(None) without a prefix is refused while any node of any graph is live.

Changed from decisions.md: **yes**. (b) upgraded from assumption to supported: plan.md:10, committed with the accepted ADR in 2b8ea46d, states the graph-blind rule, and the code comment gives its reason; the working answer becomes 'graph-blind liveness' rather than 'refuse unless ownership can be established'. (a) unchanged; added the plaintext-marker consequence (ADR-0013:51) of a stuck run.

## Alternatives

- (a1) audited cancel operation that removes the marker and writes a redaction revision for the partial run
- (a2) document re-erase-and-resume as the only recovery (as built, undocumented outside the error text)
- (b1) graph-blind liveness for every default-graph target (plan.md:10)
- (b2) refuse redact(None) without a prefix outright
