## Contradictions

- The accepted implication (a temporal edge implies a row; only the temporal side removes a marked row) conflicts with a maintainer path-matrix test that runs delete_edge on a marked triple and accepts the surviving timestamp. (CONTEXT.md:66-73; docs/adr/0009-a-temporal-edge-implies-a-structural-edge.md:11-21; tests/e2e/test_254_purge_e2e.py:322-327)
- An adopted (explicit) row is protected from temporal deletes. delete_edge still removes it while timestamps remain, which also breaks the implication. (docs/adr/0009-a-temporal-edge-implies-a-structural-edge.md:13; intent-a-hd0302-temporal-row-delete case B)

## As built

delete_edge(s, p, o, graph=g) deletes the triple's rows whether marked ({"temporal":true}) or adopted, and their ^KG entries. The temporal events stay, so get_edges_in_window still returns the edge while MATCH/adjacency readers no longer see it. A later purge removes the timestamps.

Evidence: live: intent-a-hd0302-temporal-row-delete; tested: tests/e2e/test_254_purge_e2e.py:322-327

## Intended contract

The accepted ADR-0009 and the glossary state the implication (for structural predicates). They do not address a structural delete of a marked or adopted row, and a maintainer test accepts the as-built removal. The reading is contested. Status: assumption.

## Working assumption

For structural predicates, a triple with surviving timestamps keeps a structural row. A direct delete may remove the explicit assertion, but the row must stay (or revert to marked) while timestamps remain. Model as-built option (a) as the baseline that violates the implication, and keep the ADR-0015 temporal-only opt-out separate (no row ever).

## Alternatives

- (a) delete the row and leave the temporal events (as built; maintainer-tested)
- (b) refuse while the triple has temporal events and the row is marked
- (c) delete the row and the triple's temporal events together
- (d) leave a marked row alone and delete only an explicit one (an adopted row reverts to marked)

## Discriminating check

probe (run): `intent-a-hd0302-temporal-row-delete`. fail against the CONTEXT/ADR-0009 implication. Case A (marked) and case B (adopted): after delete_edge, rows=[] and ^KG out=0, while get_edges_in_window still returns ts 1790000000. Model for the model lanes: state rows[t] in {none, marked, explicit}, ts[t] a set; actions temporal_write, temporal_delete, purge, create_edge, delete_edge; property ts[t] nonempty implies rows[t] != none for structural predicates. As built, delete_edge sets rows:=none (violation); b refuses; c clears ts; d keeps or re-marks the row.

## What would change this

A maintainer statement on whether delete_edge is allowed to break the temporal implication (confirms a), or a fix choosing b/c/d.

## Residual question for maintainer

May delete_edge remove a structural row while the triple still has timestamps (marked or adopted)? Working answer: no, the row stays or reverts to marked while timestamps remain. Best alternative: (c) delete_edge also removes the triple's temporal events.

## Consequence rank hint

medium: adjacency readers (MATCH, BFS, centrality) lose an edge the temporal index still holds; affects derived-store consistency checks
