## Contradictions

- FR-011 (decided 2026-10-20) puts a SELECT check in the executor so that 'SQL table privileges keep deciding what a caller can read'. The later R280 statement and ADMIN_GUIDE §3 make the database resource the native boundary and say the executor does not check. As built, the check is a per-engine Python routing gate. (specs/253-native-cypher-executor/spec.md:124-127; d3a86fcd; docs/ADMIN_GUIDE.md:565-570; iris_src/src/Graph/KG/Cypher/Exec.cls:33-50)
- FR-003 says ^KG is read only where Indexed() holds. The engine caches the index kind for its life, so after an out-of-band drop it would keep reading a ^KG that row writes no longer maintain. (specs/253-native-cypher-executor/spec.md:102; iris_vector_graph/engine.py:704-723)

## As built

Three facts are cached per engine: SELECT on the four tables (_native_privileges, never re-asked), the adjacency index kind (_adjacency_indexed, reset only by initialize_schema), and the executor plan version. Exec.Run checks only the plan version. Not exercised live: a REVOKE or a DROP INDEX on product tables would modify the shared namespace (the drop recompiles the table class), which lane rules forbid.

Evidence: inspected: iris_vector_graph/engine.py:559-586,704-723; inspected: iris_vector_graph/cypher/native_plan.py:524-539; inspected: iris_src/src/Graph/KG/Cypher/Exec.cls:33-50

## Intended contract

Privileges: the latest maintainer statement (R280, ADMIN_GUIDE §3) makes the database resource and %Native_* the native boundary, and even FR-011 allowed per-process caching, so prompt effect of a SQL REVOKE on running native readers is not promised. Index: FR-003 requires the route capability to hold when ^KG is read. The per-engine cache does not guarantee that after an out-of-band drop. Status: **assumption**.

## Working assumption

Split the question. (1) A SQL REVOKE is not guaranteed to reach running engines' native reads. To cut native access, revoke the database resource or %Native_ClassExecution, or start new engines. Treat FR-011's executor-side check as an unimplemented spec requirement (F-0908) whose amendment is the maintainer's call. (2) For the route capability, keep FR-003: native reads require the index to be declared at the time of the read. Model an out-of-band drop under running engines as a premise violation ('the index is not dropped while engines run'), not a supported transition, unless Run checks Indexed().

## Alternatives

- (a) keep per-engine caches; document that a revoke or index drop needs new engines
- (b) re-ask on a timer or every N reads
- (c) check privileges in Exec.Run per process and user (FR-011 literally; closes F-0908)
- (d) check Graph.KG.Adjacency.Indexed() inside Run

## Discriminating check

model, proposed: Minimal model. State: grant in {held, revoked}, index in {declared, dropped}, engine caches priv in {unset, T, F} and idx in {unset, T, F}, ^KG freshness. Actions: Read (gate evaluated through the caches), Revoke, DropIndex (out-of-band), WriteEdge (maintains ^KG only if index declared), NewEngine. Properties: P1 native read implies grant held now; P2 native read implies index declared now; P1' (FR-011 as written) native read after a revoke only by a process whose check predates the revoke. Distinguishing traces: Read;Revoke;Read (as-built violates P1, satisfies P1'); Read;DropIndex;WriteEdge;Read (as-built returns stale rows, violates P2). Live probe design (needs orchestrator approval; disposable namespace): user U with SELECT, engine as U, native read (counter +1), REVOKE SELECT ON Graph_KG.rdf_props FROM U, read again and check whether the native counter rises; restore the GRANT.

Result: not run: needs privilege or DDL changes outside lane rules; inspection shows per-engine caches and no check in Run

## What would change this

A maintainer amendment of FR-011 to the shipped design (settles the privilege half as (a)), or an executor-side check (c/d). A supported IVG operation that drops idx_edges_adj would make the index half a real transition, not a premise.

## Residual question for maintainer

Must a SQL REVOKE, or an out-of-band drop of idx_edges_adj, take effect on engines already running? FR-011 (decided 2026-10-20) says the executor checks SELECT 'cached per process and user'. R280 (2026-11-04) says native callers do not check and the database resource is the boundary. Which is the contract, and should FR-011 be amended? Working answer: database resource is the boundary, so document that a SQL revoke needs new engines; require Indexed() at read time. Best alternative: check privileges and Indexed() in Exec.Run (FR-011 literal).
