## Contradictions

- `spec.md:16-18, 42-44, 126 (one graph per tenant; no record holds the tenant's ids; verify equal)` vs `ADR-0013:37; plan.md:9 (node records reachable only by prefix)`: For unprefixed ids in a per-tenant graph, erase_graph + redact(graph) completes, leaves the tenant's node ids and values in the history and verify() diverges; no product call can address those records without also hitting other tenants (F-1304).
- `c53c654a R290 ('the ledger keeps nodes in the default graph')` vs `LedgerGenesis.cls:14-20 (captures every graph's nodes as graph '' records)`: A named-graph node captured at genesis is attributed to the default graph's node history; the provenance needed to redact it by graph is lost at capture time.
- `spec.md:127-128 FR-008 (receipt says what stays out of reach)` vs `LedgerRedact.cls:505-509 (out_of_reach lists exports, journals, backups only)`: The receipt reports complete=true and does not mention the unredacted node records.

## As built

Nodes in a per-tenant graph with unprefixed ids: erase_graph(gA) + redact(gA) completes (1 relationship record tombstoned); the tenant's node ids and property values stay in the node records; the receipt says complete and lists only exports/journals/backups as out of reach; verify() diverges (2 differences); a prefix call cannot express the tenant.

Evidence: live `ib-HD1304-graph-per-tenant`; inspected `iris_src/src/Graph/KG/LedgerGenesis.cls:14-36; LedgerApply.cls:215-251`

## Intended

Status: **assumption**. Supported at this pin that node records are addressable only by id prefix (accepted ADR-0013:37), so the documented tenant procedure presupposes tenant-prefixed ids. What a graph-per-tenant tenant with unprefixed ids should get is not settled: the spec promises erasure for exactly that deployment, the ADR gives no route.

## Working assumption

Require tenant id prefixes for ledger-governed tenants and document it next to redact(); for a graph target whose erased nodes left graph-blind node records, return an explicit incomplete result (or refuse) instead of complete=true. Model graph-qualified node records for future history separately; a migration of existing history needs trustworthy provenance, which the genesis did not keep.

Changed from decisions.md: **no**. Same choice; added the R290 maintainer statement, the genesis attribution contradiction, the receipt (FR-008) gap and fresh live evidence including the FR-007 divergence.

## Alternatives

- (a) record the node's graph in node records (layout change; existing graph-blind history stays ambiguous)
- (b) require and document tenant id prefixes; flag or refuse unattributable graph targets
- (c) graph-only tenant erasure via a provenance migration that reconstructs node graphs from trusted sources

## Residual question for the maintainer

For one graph per tenant with unprefixed node ids, must tenant erasure work (record node graphs and migrate), or are tenant prefixes required, with redact(graph) reporting the node history it cannot reach? Working answer: prefixes required plus an explicit incomplete result. Best alternative: graph-qualified node records going forward.

Consequence rank hint: high (tenant erasure silently incomplete for the spec's own deployment (privacy, S1))
