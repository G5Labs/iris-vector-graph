## Contradictions

- The ledger contract says strict mode skips the structural mirror; since 43efd473 the server asserts row and endpoints regardless, and live strict-mode writes created node rows e,f and a marked row. (`specs/213-graph-revision-ledger/contracts/ledger-api.md:92`; `commit 43efd473`; `live intent-a-hd0501-temporal-endpoints`)
- The decision says a temporal mirror 'is no longer an unrecorded write'; verify reports the endpoint nodes the mirror created as unrecorded_writes, on the engine path and right after a ledger commit of a changeset temporal op. (`commit 43efd473`; `live intent-a-hd0501-temporal-endpoints`)
- A changeset relationship refuses missing endpoints or records stubs; a changeset temporal op creates them unrecorded. (`docs/USER_GUIDE.md:1103-1104`; `iris_src/src/Graph/KG/LedgerApply.cls:613-641`)
- The upstream test's 'verify equal' holds only because its endpoint ids already exist (verify compares node ids graph-blind). (`tests/integration/test_ledger_us11_temporal_coexist.py:108-122`; `iris_vector_graph/ledger/replay.py:600`)

## As built

With the adjacency index, every structural temporal write (engine path, changeset op, and strict mode) inserts missing endpoint rows in the edge's graph plus a marked edge row; no create_node is recorded; strict mode does not refuse. verify() skips the marked row but reports the endpoint nodes as unrecorded_writes; reconstruct() omits them; a later purge_raw_before (retire_bare_nodes=True default) deletes them, also unrecorded.

Evidence: live `intent-a-hd0501-temporal-endpoints`; inspected `iris_src/src/Graph/KG/Adjacency.cls:575-613`; inspected `iris_src/src/Graph/KG/LedgerApply.cls:613-641`

## Intended contract

The 2026-10-19 maintainer decision treats a temporal write's structural mirror as derived from the temporal store, outside revisions and not an unrecorded write; the same commit makes the mirror include the endpoints. So endpoint rows a temporal write creates should not surface as unrecorded writes: either excluded from verify/genesis by an identifiable rule, or (for changeset ops) recorded like auto-stubbed relationship endpoints. The decision names the row explicitly, the nodes only by implication. Status: assumption.

## Working assumption

Engine-path endpoints: derived, with identifiable provenance (e.g. the 'bare temporal endpoint' rule purge already uses) and excluded from genesis/verify; changeset temporal ops: follow the relationship endpoint rule (refuse a missing endpoint or record a stub). Keep their real effects in the environment model; treat ledger-api.md:92 as stale for the indexed path.

## Alternatives

- (a) record create_node for endpoints a changeset temporal op creates; strict mode refuses an engine temporal write with missing endpoints
- (b) mark endpoints as derived (column/registry or 'bare temporal endpoint' rule) and leave them out of genesis and verify
- (c) a temporal write never creates nodes; callers pre-create them, as create_rel requires
- (d) document them as unrecorded writes (status quo)

## Discriminating check

probe (run): `intent-a-hd0501-temporal-endpoints`. fail: engine, changeset and strict paths all created unrecorded endpoint rows; verify diverged (unrecorded_writes) naming them, including immediately after a successful ledger commit; strict mode did not skip the mirror.

## What would change this

A maintainer statement whether the 'temporal mirror' of 43efd473 includes its endpoint nodes; or a decision that temporal endpoints must pre-exist when the ledger is on.

## Residual question for maintainer

Are node rows created by a temporal write part of the derived 'temporal mirror' (decided for the row on 2026-10-19) that verify must skip, or governed nodes that must be recorded or pre-created? Does ledger-api.md:92 ('strict mode skips the structural mirror') still stand?

## Consequence rank hint

high: any temporal workload with the ledger on makes verify report divergence (false unrecorded writes) and strict mode does not prevent it; erasure/redaction reasoning depends on knowing which writes the ledger saw.
