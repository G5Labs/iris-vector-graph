## Contradictions

- The maintainer says 'one schema path: initialize_schema()', but still maintains and tests a deployer that runs the pre-spec-227 sql/schema.sql and unqualified operators_fixed.sql. (tests/unit/test_setup_iris.py:1-8; scripts/deploy_production.py:65; tests/unit/test_470_scripts_tcp_run.py:245)
- The legacy deployer installs unqualified procedures (default schema User), against spec 262's qualification rule. (specs/262-ivg-owned-sql-schema/spec.md FR-008; sql/operators_fixed.sql:4-45)

## As built

initialize_schema loads none of sql/. The sdist ships sql/ without its loaders. scripts/deploy_production.py, maintained in 4.7.0 but neither documented nor packaged, runs sql/schema.sql + sql/operators_fixed.sql. scripts.setup.load_fraud_data loads sql/fraud_sample_data.sql for the demo. The other files have ad-hoc or no loaders.

Evidence: inspected: pyproject.toml:181-183; scripts/deploy_production.py:43-65; tested: tests/unit/test_470_scripts_tcp_run.py:245-255

## Intended contract

The product install path is initialize_schema() (maintainer statement 04bf1c67). sql/ is not part of that path. No source says whether the shipped legacy files and the maintained legacy deployer are supported, historical or to be removed. Status: assumption.

## Working assumption

Inventory both install paths. The product contract (spec 262 schema, inventory test) covers initialize_schema only. scripts/deploy_production.py + sql/schema.sql + sql/operators_fixed.sql form a reachable legacy path that produces a non-conforming namespace (DDL-only before its class step, unqualified procedures). sql/fraud_sample_data.sql is maintained demo data. Files with no loader are historical material.

## Alternatives

- (a) keep as historical samples, marked as such
- (b) delete them and the scripts that load them
- (c) bring them in line with the IVG Schema (or have deploy_production call initialize_schema)

## Discriminating check

inspection (run): `pyproject.toml:181-183; scripts/deploy_production.py; tests/unit/test_470_scripts_tcp_run.py`. Reachability settled by inspection. A live run of the legacy deployer would need a scratch namespace and is not needed to classify the files.

## What would change this

A maintainer statement that deploy_production.py is a supported production installer (then sql/schema.sql and operators_fixed.sql are product and violate spec 262), or a removal decision.

## Residual question for maintainer

Is scripts/deploy_production.py (sql/schema.sql + sql/operators_fixed.sql) a supported install path, and should the sdist keep shipping sql/? Working answer: legacy and unsupported; initialize_schema is the only product path. Best alternative: make the legacy deployer call initialize_schema and retire the old SQL.
